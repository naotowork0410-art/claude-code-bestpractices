### Claude Fable 5 ― エージェントタスク向け新最高峰モデル

**発見内容**: Anthropic が 2026年6月9日に **Claude Fable 5**（Mythos クラス、Opus の上位）をリリース。Claude Code のエージェントハーネスで「数日間」稼働し続けられる設計で、計画→進捗確認→改善のサイクルを自律的に回せる。1Mトークンコンテキストウィンドウを持ち、テキスト・画像・ファイルに対応。Opus 4.8 より難しいタスクで高いスコアを記録。

なお2026年6月12日時点で、米国政府指令への準拠のため GitLab Duo Agent Platform への Fable 5 アクセスは一時停止されている。

**適用提案**:
- 長時間の自律エージェントタスク（大規模リファクタリング・マルチファイル移行など）には `claude-fable-5` モデルを指定
- `.claude/agents/heavy-refactor.md` のフロントマターで `model: fable-5` と指定し、長時間タスクのみ切り替え
- `claude --model claude-fable-5 -p "..."` で非インタラクティブバッチにも適用可能

### プラグインマーケットプレイス ― 101+ プラグインの活用

**発見内容**: 公式マーケットプレイス（`claude-plugins-official`）が Claude Code 起動時に自動利用可能。2026年3月時点で **101 プラグイン**（Anthropic 製 33 / パートナー製 68）が公開。`/plugin` コマンドでブラウズ・インストールできる。

#### Anthropic 製プラグインカテゴリ
| カテゴリ | 内容 |
|---------|------|
| **Code Intelligence** | LSP プラグイン（pyright, rust-analyzer, gopls, jdtls 等） |
| **Dev Workflow** | git, CI/CD 連携ツール |
| **Setup Tools** | プロジェクト初期化補助 |

#### パートナープラグイン（代表例）
GitHub / Playwright / Supabase / Figma / Vercel / Linear / Sentry / Stripe / Firebase

#### Code Intelligence プラグインで得られる機能
- ジャンプ・トゥ・定義 / 参照検索
- 編集直後の型エラー検出（LSP）
- ファイル全読み込みの削減 → コンテキスト節約

```bash
# LSP プラグインのインストール例（Python）
/plugin install pyright-lsp

# Rust 環境
/plugin install rust-analyzer-lsp
```

**適用提案**:
- 型付き言語のプロジェクトでは `/plugin install <lang>-lsp` を真っ先に実行する
- パートナープラグイン（Sentry, Linear 等）で外部サービスへのコンテキスト切り替えをゼロにする
- プロジェクト `.claude-plugin/plugin.json` でバージョンを固定し `git` 管理する

### 敵対的レビューパターン ― サブエージェントによる差分検証

**発見内容**: 公式ベストプラクティスで「adversarial review step」が明文化された。実装したセッションとは **別のサブエージェント**（新鮮なコンテキスト）に差分を見せてレビューさせることで、実装バイアスを排除できる。組み込みの `/code-review` スキルがこの用途に最適。

#### `/code-review` スキルの使い方

```text
# 差分を現在のコンテキストに汚染せずレビュー
/code-review

# または明示的なサブエージェント指示
use a subagent to review the rate limiter diff against PLAN.md.
Check that every requirement is implemented, the listed edge cases
have tests, and nothing outside the task's scope changed.
Report gaps, not style preferences.
```

#### 重要な注意点

> レビュアーに「ギャップを見つけろ」と指示すると、実装が健全でも何かを報告する。すべての指摘を追うと過剰エンジニアリング（不要な抽象化・防御的コード）に陥る。**「正確さや要件に影響するもののみフラグを立てよ」**と制約すること。

**適用提案**:
- 大型機能の実装後は必ず `/code-review` を実行してから PR を出す
- `PLAN.md` を事前に書いておき、レビュアーサブエージェントに照合させる
- 「スタイル指摘は無視、正確さのみ」と明示することで過剰対応を防ぐ

### `/rewind` 2モードの使い分け ― "from here" vs "up to here"

**発見内容**: `Esc+Esc` または `/rewind` で開くメニューに、**Summarize from here** と **Summarize up to here** の 2 種のサマリーモードがあることが公式ドキュメントで明確化された。単なる「巻き戻し」ではなく、セッション内のコンテキスト管理に使える。

| オプション | 動作 | 使いどころ |
|-----------|------|-----------|
| **Restore conversation** | 会話のみ指定点に戻す | コード変更は維持、会話だけやり直したい |
| **Restore code** | コードのみ指定点に戻す | 会話履歴は維持、コードだけ戻したい |
| **Restore both** | 会話+コードを完全復元 | 完全にやり直す |
| **Summarize from here** | その点以降のメッセージを圧縮 | 最新の会話を保持しつつ古い履歴を整理 |
| **Summarize up to here** | その点以前のメッセージを圧縮 | 最近の会話は詳細のまま、序盤を整理 |

**適用提案**:
- 長いデバッグセッション後、「ここまでの試行結果は不要、最新の方針だけ残したい」→ **Summarize up to here** を選択
- PR レビュー対応中に実装の詳細をまとめたい → **Summarize from here** を使い序盤の探索を保持
- コード変更は正しいが会話が迷走した場合 → **Restore conversation** のみ

### 公式認定 5 つのアンチパターン ― 失敗の早期検知

**発見内容**: Anthropic 公式ドキュメントが **Claude Code の典型的な失敗パターン 5 つ** を明文化。各パターンに対処法がセットで提供された。

| アンチパターン | 症状 | 対処 |
|---------------|------|------|
| **Kitchen Sink Session** | 関係ないタスクを混在させる | タスク切り替えで `/clear` |
| **Correcting Over and Over** | 同じ修正を 2 回以上繰り返す | `/clear` + より具体的な初期プロンプト |
| **Over-specified CLAUDE.md** | 長すぎて重要ルールが埋もれる | 容赦なく削除。フックに移行できるものは移行 |
| **Trust-then-Verify Gap** | エッジケースを未検証で出荷する | 常にテスト・スクリプト・スクリーンショットで検証手段を用意 |
| **Infinite Exploration** | スコープなき "調査" で数百ファイルを読む | 調査はサブエージェントへ委譲、スコープを明示 |

#### CLAUDE.md 削除の判断基準（公式）

> **「その指示がなくても Claude が正しく動くなら、削除するかフックに変換せよ」**

```markdown
<!-- 削除候補の判定チェックリスト -->
- [ ] この行がなくても Claude は正しく動く  → 削除
- [ ] この行は "clean code を書け" 等の自明な内容 → 削除
- [ ] この行は頻繁に変わる情報 → 削除（代わりに /btw か MCP）
- [ ] この行はコードを読めば Claude が推測できる → 削除
- [ ] この行は毎回ではなく時々だけ必要 → Skills へ移行
```

**適用提案**:
- 既存 CLAUDE.md を上記チェックリストで審査し、削除 or Skills/hooks 移行を実施
- 「Claude に 2 回同じ修正をした」と気づいた時点で即 `/clear` + プロンプト改善
- 月 1 回 CLAUDE.md を `/init` 出力と比較し、不要行をプルーニングするルーティンを設ける

### ファンアウトスケーリング ― `--allowedTools` と `--permission-mode auto`

**発見内容**: 公式ドキュメントで大規模ファイル移行・分析のための非インタラクティブファンアウトパターンが体系化された。`--allowedTools` でバッチ実行時の権限を最小化し、`--permission-mode auto` で自動安全審査を有効化できる。

#### ファンアウトパターン（Python → 別フレームワーク移行例）

```bash
# ステップ1: 対象ファイルリストを生成
claude -p "List all Python files that need migrating" --output-format json > files.json

# ステップ2: 並列ファンアウト（最大5並列）
cat files.json | jq -r '.[]' | xargs -P 5 -I {} \
  claude -p "Migrate {} from Django to FastAPI. Return OK or FAIL." \
  --allowedTools "Edit,Bash(git commit *)"

# ステップ3: 本番実行は auto モードで安全審査付き
claude --permission-mode auto -p "fix all lint errors"
```

#### `--permission-mode auto` の動作

- **Classifier モデルが各コマンドを事前審査**し、リスクのある操作をブロック
- スコープ逸脱・未知インフラ・ホスティングコンテンツ起因の操作を遮断
- `-p` フラグ（非インタラクティブ）時に繰り返しブロックされると自動中断

#### `--output-format` の使い分け

```bash
# 人間向け確認
claude -p "List API endpoints" --output-format text

# スクリプト連携
claude -p "Analyze dependencies" --output-format json | jq '.dependencies'

# リアルタイム処理（大きなログ解析等）
claude -p "Parse error log" --output-format stream-json --verbose
```

**適用提案**:
- CI/CD パイプラインへの Claude 統合には `claude -p` + `--output-format json` を使う
- バッチ実行時は `--allowedTools` で必要ツールだけに制限し誤操作を防ぐ
- `--permission-mode auto` を CI 向け実行に追加してセキュリティレイヤーを確保
- `--verbose` は開発中のみ、プロダクションでは外す

### MCP 2.4 ― エンタープライズガバナンス強化

**発見内容**: MCP 2.4 仕様（2026年）でエンタープライズ向け機能が追加された。

| 機能 | 内容 |
|------|------|
| **MFA for high-risk tools** | リスクの高いツール呼び出しに多要素認証 |
| **Real-time audit logs** | MCP Admin Console からリアルタイムで監査ログ確認 |
| **Enhanced consent workflows** | 同意フロー改善 |
| **OAuth 2.1 standard** | HTTP トランスポートが OAuth 2.1 に標準化（SSE 非推奨） |

#### セキュリティファースト MCP 構成の原則

```
1. Read-only から始める（GitHub MCP はイシュー読み取りのみ等）
2. 本当に使うサーバーだけ追加（3〜5個を上限の目安）
3. `.mcp.json` に API キーを直書きしない（${ENV_VAR} 形式）
4. 各サーバーのスコープを「実際のユースケース」に絞る
5. Tool Search 機能（Sonnet 4 以上）でコンテキスト削減
```

**適用提案**:
- Team/Enterprise 環境では `managed-mcp.json` への移行を検討し、MFA/監査ログを活用
- `.mcp.json` の `"transport": "http"` + OAuth 2.1 への移行を進める（SSE は非推奨化）
- 組織内で「MCP サーバー追加時は読み取り専用スコープから開始」をポリシー化する

# Claude Code ベストプラクティス調査レポート 2026-08-24

## 今週の新発見

### Output Styles: 5種の全容 + カスタム output style（v2.1.237）

**発見内容**: v2.1.237（2026-08-19）で **Concise** スタイルが追加され、組み込みスタイルが計5種類に確定した。

| スタイル | 動作 |
|---------|------|
| **Default** | 従来の Claude Code エンジニアリング向け標準スタイル |
| **Proactive** | 即時実行・自動仮定・計画より行動優先（auto mode より強い自律実行、permission mode は変更なし） |
| **Concise** | 結果ファーストで前置き・ナレーションを省略。エラー報告・破壊的操作の確認は省略しない（v2.1.237+） |
| **Explanatory** | コーディング中に「Insights」で実装意図を解説 |
| **Learning** | 協調学習モード。コード内に `TODO(human)` マーカーを置いてユーザーに実装を促す |

**重要な動作ルール**:
- Output Styles はメイン会話にのみ適用。**サブエージェントには引き継がれない**（例外: `fork` はシステムプロンプトを継承するため有効）
- 設定変更は `/clear` または新セッション開始後に反映

**カスタム Output Style**:
```markdown
# .claude/output-styles/diagram-first.md
---
name: Diagrams first
description: Lead every explanation with a diagram
keep-coding-instructions: true   # コーディング指示を維持しながら追加
---

When explaining code or architecture, start with a Mermaid diagram (flowchart TD
or sequenceDiagram), then explain in prose. Keep diagrams under 15 nodes.
```

カスタムスタイルの保存先:
- ユーザーレベル: `~/.claude/output-styles/`
- プロジェクトレベル: `.claude/output-styles/`
- 管理ポリシー: managed settings ディレクトリ内の `.claude/output-styles/`

プラグインに同梱する場合は `force-for-plugin: true` でプラグイン有効時に自動適用できる。

**適用提案**:
- コードレビュー中の冗長な前置きが煩わしい場合は `settings.local.json` に以下を追加:
  ```json
  { "outputStyle": "Concise" }
  ```
- チームで共通スタイルを使う場合は `managed-settings.d/10-output-style.json` に設定を配置
- カスタムスタイルは `.claude/output-styles/` に置き、`/config` から選択可能。`keep-coding-instructions: true` を忘れるとコーディング指示が失われるので注意
- Proactive スタイルは長時間バッチタスクで有効。ただし permission mode とは独立して動作するため `permissions.deny` の設定は引き続き機能する

### サブエージェント フロントマター 公式完全版

**発見内容**: 公式ドキュメントが更新され、`.claude/agents/<name>.md` で使用できる全フロントマター項目が確定した。

**コア設定**:

| フィールド | 必須 | 内容 |
|-----------|------|------|
| `name` | Yes | ユニーク識別子（小文字・ハイフンのみ） |
| `description` | Yes | Claude が委譲するタイミングの説明 |
| `tools` | No | 許可ツールの許可リスト（未指定は全継承） |
| `disallowedTools` | No | 拒否ツール（`mcp__github` でサーバー丸ごと拒否可） |
| `model` | No | `sonnet`/`opus`/`haiku`/`inherit`（デフォルト） |

**高度なオプション（完全版）**:

```yaml
---
name: advanced-agent
description: 高度な例
tools: Read, Grep, Glob, Bash
disallowedTools: Write
model: sonnet
permissionMode: default        # default/acceptEdits/auto/dontAsk/bypassPermissions/plan
maxTurns: 10                   # 最大エージェントターン数
skills:
  - api-conventions            # 起動時にプリロードするスキル
mcpServers:
  - github                     # 参照（既存サーバーを使用）
  - playwright:                # インライン定義（このエージェント専用）
      type: stdio
      command: npx
      args: ["-y", "@playwright/mcp@latest"]
memory: project                # user / project / local
background: true               # 強制バックグラウンド実行
effort: high                   # low/medium/high/xhigh/max
isolation: worktree            # git worktree で分離実行
color: blue                    # agents ビューでの表示色
initialPrompt: "Start by..."   # 起動時の初期プロンプト
hooks:
  PreToolUse:
    - matcher: "Bash"
      hooks:
        - type: command
          command: "./validate.sh"
---
```

**サブエージェント起動時にロードされるもの**:
- システムプロンプト（agent 定義、フルの Claude Code プロンプトではない）
- タスクメッセージ（親セッションの委譲プロンプト）
- CLAUDE.md 階層（Explore/Plan エージェントは除く）
- Git status スナップショット
- プリロードスキル（`skills:` フィールド）
- 同一セッションの他エージェント一覧（v2.1.206+）

**引き継がれないもの**: Output Style・メイン会話の auto memory・コンテキストウィンドウサイズ

**適用提案**:
- `permissionMode: plan` を使うと「提案のみ・実行なし」の読み取り専用エージェントになり、セキュリティ審査エージェントに最適
- `isolation: worktree` は並列ファイル編集時の競合防止に使用（~200-500ms のセットアップコストあり。軽量タスクには不要）
- `hooks` をフロントマターに直接書くことで、そのエージェント専用の PreToolUse/PostToolUse を設定できる（グローバルフックと分離できる）
- `maxTurns: 10` を設定して暴走を防止（デフォルトは無制限）

### サブエージェント 呼び出し保証構文 & CLI フラグ

**発見内容**: サブエージェントを「確実に」使わせる方法が公式ドキュメントに明記された。

```text
# 自然言語（Claude が判断して委譲）
Use the code-reviewer to analyze this function

# @"agent-name (agent)" 構文（確実に使用を保証）
@"code-reviewer (agent)" review the authentication module

# セッション全体でデフォルトエージェントを指定
claude --agent code-reviewer
```

また settings.json で永続的なデフォルトエージェントを設定:
```json
{
  "agent": "code-reviewer"
}
```

**適用提案**:
- 特定フェーズで必ず特定エージェントを使わせたい Routine では `@"agent-name (agent)"` 構文でプロンプトを固定する
- `--agent` フラグはスクリプト化した CI/CD の自動化タスクで有用

### CLAUDE.md / Output Styles / Skills / Subagents 公式比較フレームワーク

**発見内容**: 公式ドキュメントが機能選択の比較表を整備。どの機能をいつ使うべきかが明確化された。

| 機能 | 動作方式 | 使うべき場面 |
|------|---------|------------|
| **Output Styles** | システムプロンプトを直接変更 | 毎ターン同じ役割・口調・出力形式が欲しい場合 |
| **CLAUDE.md** | システムプロンプト後にユーザーメッセージとして追加 | プロジェクト規約・コードベースの常時コンテキスト |
| **`--append-system-prompt`** | システムプロンプトへの追記（削除なし） | 単発呼び出しでの一時的な追加 |
| **Subagents** | 独自のシステムプロンプト・モデル・ツールで実行 | フォーカスしたタスク用の独立したヘルパー |
| **Skills** | 呼び出し時・関連時にロード | 再利用可能なワークフロー |

これと既存の「強制→Hooks、知識→Skills、委譲→Subagents、常時ガイダンス→CLAUDE.md」の 4 象限と組み合わせると意思決定が完全になる。

**適用提案**:
- 「毎回同じ指示を再入力している」→ Skills か Output Styles か CLAUDE.md のどれかに移行。上の表で判断する
- Output Style はシステムプロンプトを直接書き換えるため、カスタム Style を多用すると内容が競合しやすい。1 セッション 1 スタイルを原則に

### Concise スタイルとプロンプトキャッシュの関係

**発見内容**: Output Style 変更はシステムプロンプトを変更するため、プロンプトキャッシュに影響する。

- セッション開始後に outputStyle を変更した場合、次の `/clear` またはセッション再起動まで反映されない
- キャッシュは「最初のリクエスト後」から有効になるため、スタイル変更直後はキャッシュミスが発生する
- Concise スタイルはアウトプットトークンを削減する一方、Explanatory/Learning スタイルは増加させる（インプットトークンのキャッシュは変わらない）

**適用提案**:
- 頻繁に Output Style を切り替えるよりも、プロジェクトごとに `settings.local.json` で固定する方がキャッシュ効率が高い
- 長時間 Routine タスクでは Concise スタイルを指定してアウトプットコストを削減する（Routine の response は誰も読んでいないため詳細な説明は不要）

## 今週の適用アクションリスト

- [ ] **`outputStyle: "Concise"` を日常作業の `settings.local.json` に設定**: v2.1.237 以降で利用可能。前置きなしで結果ファーストのレスポンスになる
- [ ] **Routine タスク用プロジェクトの `.claude/settings.json` に `outputStyle: "Concise"` を追加**: 誰も読まないステータス更新の出力トークンを削減
- [ ] **カスタム Output Style を `.claude/output-styles/` に作成**: `keep-coding-instructions: true` を付けてコーディング指示を維持しつつ、チーム固有の応答形式を定義
- [ ] **サブエージェントの `maxTurns` を設定**: 無制限実行のリスクを避けるため、ユースケースに応じた上限を `maxTurns: 10〜20` で設定
- [ ] **高頻度使用エージェントのフロントマターに `hooks` を追加**: グローバルフックと分離してエージェント固有のバリデーションを実装
- [ ] **`permissionMode: plan` の読み取り専用エージェントを作成**: コードレビュー・セキュリティ審査など、変更なしで分析だけ行うエージェントに適用
- [ ] **`@"agent-name (agent)"` 構文を Routine プロンプトに組み込む**: 特定エージェントの使用を保証し、Claude の自動判断に依存しない設計に
- [ ] **Output Style vs Skills vs CLAUDE.md の使い分けを既存設定でレビュー**: 「毎回同じ指示」が CLAUDE.md に蓄積している場合、Output Style またはスキルへ移行を検討

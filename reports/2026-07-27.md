# Claude Code ベストプラクティス調査レポート 2026-07-27

## 今週の新発見

### モデル設定: Opus 5 デフォルト化 + `fallbackModel` チェーン（v2.1.219）

**発見内容**: v2.1.219（7/24）で `opus` エイリアスが **Claude Opus 5** に更新された。Opus 5 は 1M トークンコンテキスト・Fast mode $10/$50/MTok。同時に Fable 5 / Opus 5 の **コンテンツベース自動フォールバック**が動作する。

| モデル | biology フラグ | cybersecurity フラグ |
|--------|---------------|---------------------|
| Fable 5 | Opus 5 へ切替 | Opus 4.8 へ切替 |
| Opus 5 | 拒否（フォールバックなし） | Opus 4.8 へ切替 |

また **`fallbackModel` チェーン**（Week 24 から GA）で可用性ベースのフォールバックも設定可能になった。

```json
// .claude/settings.json
{
  "fallbackModel": ["claude-sonnet-5", "claude-haiku-4-5"]
}
```

```bash
# セッション単位では --fallback-model フラグ（最大3エントリ）
claude --fallback-model sonnet,haiku
```

- フォールバックはそのターンのみ有効（次のメッセージでは primary に戻る）
- `/status` には表示されない。切替時にトランスクリプト内通知で初めて分かる
- `availableModels` の外にあるエントリは自動除外される

**適用提案**:
- `~/.claude/settings.json` に `"fallbackModel": ["sonnet", "haiku"]` を追加してAPIの過負荷時の失敗を防ぐ
- Fable 5 を使うタスクにセキュリティ/生物系コードを含む場合は自動フォールバック先が変わることを把握しておく
- モデルをピン留めしたい場合は `"model": "claude-opus-5"` のようにフルIDを指定する（エイリアスはバージョンアップで変わる）

### ネスト型サブエージェント: デフォルト深さ3に統一（v2.1.219）

**発見内容**: v2.1.172（6/10）で最大5階層のサブエージェントネストが解禁されたが、7/21〜7/24 の一連の変更を経て **現在のデフォルトは深さ3**（`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` で制御）に固定された。サブエージェントパネルにはツリー全体と各ノードの子孫数が表示される。

```bash
# ネスト無効化（深さ1 = サブエージェントがサブエージェントを起動できない）
export CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1

# 深さ5に拡張（コスト・ループリスクに注意）
export CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=5
```

階層型パターンの設計例（深さ3）:

```
Main: "認証モジュールをリファクタリング"
  └─ Subagent L1: "テストを書く"（L2: "ユニットテスト生成", L2: "統合テスト生成"）
  └─ Subagent L1: "ドキュメントを更新"
```

**適用提案**:
- CI/Routines では `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` を設定してループリスクを排除
- 大規模リファクタリングや「調査→分析→修正」のような3段パイプラインでは深さ3を活用する
- `/agents` でツリーを監視し、意図しない深さのネストが起きていないか確認する

### `--safe-mode` によるトラブルシューティング（v2.1.169）

**発見内容**: `--safe-mode`（または環境変数 `CLAUDE_CODE_SAFE_MODE`）でClaude Codeを起動すると、すべてのカスタマイズが無効化された **クリーンな状態**でセッションを開始できる。

無効化されるもの:
- `CLAUDE.md`（全階層）
- Skills / Commands
- Plugins
- Hooks
- MCP サーバー
- カスタムエージェント

有効なまま: 認証・モデル選択・ビルトインツール・パーミッション

```bash
# カスタマイズを全部切って起動
claude --safe-mode

# 環境変数での永続指定（CI 向け）
export CLAUDE_CODE_SAFE_MODE=1
claude
```

セーフモードで問題が消えた場合 → CLAUDE.md / Skills / Hooks / MCP のいずれかが原因。

**適用提案**:
- 動作がおかしいときは最初に `claude --safe-mode` で再現確認する
- セーフモードで正常動作する場合は、MCP → hooks → CLAUDE.md の順に一つずつ戻して原因を特定する
- CI で全カスタマイズを無効にしたい場合は `CLAUDE_CODE_SAFE_MODE=1` を環境変数に設定する

### `/cd` コマンドによるセッション移動（v2.1.169）

**発見内容**: `/cd` コマンドでセッションをプロンプトキャッシュを再構築せずに **別ディレクトリへ移動**できるようになった。新ディレクトリの `CLAUDE.md` はシステムプロンプト置換でなくメッセージとして追記される。

```text
# 現在のセッションごと別プロジェクトへ移動
> /cd ../other-project

# 信頼確認が出た場合は y で承認
```

重要な動作:
- プロンプトキャッシュは**再構築されない**（コスト節約）
- セッションは新ディレクトリの project storage へ移行し、`--resume` でそこから再開可能
- 新しいディレクトリを初めて使う場合は trust 確認が出る

**適用提案**:
- モノレポ内で複数パッケージを順番に作業する場合に `/cd` で移動するとコンテキストを保ちながら効率よく作業できる
- `--safe-mode` で起動してから `/cd` で作業ディレクトリへ移動するパターンはセキュリティチェックにも使える

### 新しい sandbox 設定（v2.1.216・v2.1.219）

**発見内容**: sandbox の制御粒度が細かくなり、ファイルシステム隔離とネットワーク制御を独立して設定できるようになった。

```json
// ネットワーク制御は維持しつつファイルシステム隔離を無効化（パフォーマンス優先）
{
  "sandbox": {
    "filesystem": {
      "disabled": true
    }
  }
}

// 許可リスト外のホストへの接続を確認なしで拒否（厳格モード）
{
  "sandbox": {
    "network": {
      "strictAllowlist": true
    }
  }
}
```

**適用提案**:
- 開発環境では `sandbox.filesystem.disabled: true` でファイルシステム隔離のオーバーヘッドを除去しつつネットワーク制御は維持する
- 本番環境やセキュリティ重視の CI では `sandbox.network.strictAllowlist: true` を設定して意図しない外部通信をブロックする

### `/code-review` のバックグラウンドサブエージェント化（v2.1.218）

**発見内容**: `/code-review` が**バックグラウンドサブエージェント**として実行されるようになり、レビュー結果がメイン会話のコンテキストを消費しなくなった。これはコンテキスト節約において非常に大きな改善。

```text
# 実行すると即座に制御が戻り、バックグラウンドでレビューが走る
> /code-review

# 完了通知が届いたら確認
> /agents
```

合わせて `/ultrareview` が記述的な引数を受け入れるようになった:
```text
> /ultrareview 認証周りの変更をレビューして
```

**適用提案**:
- 実装完了後に `/code-review` を走らせる習慣をつける（v2.1.215 から自動実行が廃止されたため手動が必要）
- `Stop` フックで `/code-review` を自動起動するのではなく、実装フロー内に明示的なステップとして組み込む
- バックグラウンドサブエージェントとして走るため、長い実装セッションでも実行コストが小さくなった

### `disableBundledSkills` でコンテキスト削減（Week 24）

**発見内容**: `disableBundledSkills: true` を設定すると、組み込みスキル・ワークフロー・ビルトインコマンドをモデルから完全に隠せる。コンテキスト圧迫の原因となるバンドルスキルを排除したいチーム向け。

```json
// .claude/settings.json
{
  "disableBundledSkills": true
}
// または環境変数
// CLAUDE_CODE_DISABLE_BUNDLED_SKILLS=1
```

否定リスト方式の deny rules も強化: ツール名の位置にグロブが使えるようになった。

```json
{
  "permissions": {
    "deny": [
      "*"          // 全ツールを拒否
    ]
  }
}
```

未知のツール名が deny ルールに含まれていると起動時に警告が出るようになった。

**適用提案**:
- 作業に不要な組み込みスキルが多い場合は `disableBundledSkills: true` を試す
- `/usage` コマンドで各スキル・MCP・プラグインのコンテキストコストを確認してから削減対象を選ぶ

### 新しい Hooks イベント（v2.1.219・v2.1.213）

**発見内容**: 2つの新しいフックイベントが追加された。

**`DirectoryAdded` フック（v2.1.219）**: `/add-dir` または SDK の `register_repo_root` で新しい作業ディレクトリが登録されたときに発火。

```json
{
  "hooks": {
    "DirectoryAdded": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "echo 'New dir added: $CLAUDE_NEW_DIRECTORY' | tee -a ~/.claude/dir-audit.log"
          }
        ]
      }
    ]
  }
}
```

**`SessionStart` の `source: "fork"` 属性（v2.1.213）**: `/fork` 経由でセッションが開始された場合、`SessionStart` フックの入力に `source: "fork"` が含まれる。

```bash
# フォーク起動とオリジナル起動を区別する SessionStart フック
if [ "$CLAUDE_SESSION_SOURCE" = "fork" ]; then
  echo "Fork セッション: ログ出力を分離" >&2
fi
```

**適用提案**:
- `DirectoryAdded` フックでディレクトリ追加の監査ログを記録する
- `SessionStart` で `source: "fork"` を確認し、フークセッションには別のコンテキストを注入するパターンを実装する

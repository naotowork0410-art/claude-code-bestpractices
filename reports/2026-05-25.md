# Claude Code ベスプラ調査レポート 2026-05-25

## 今週の新発見

### コンテキストコスト全体像 ― 公式フィーチャー別コスト表と `disable-model-invocation` 活用

**発見内容**: 公式ドキュメント（Extend Claude Code）が全機能のコンテキストコストを一覧表で整理し、コスト削減のための具体的な設定も明記した。

#### 機能別コンテキストコスト一覧（公式）

| 機能 | ロードタイミング | コスト |
|------|----------------|--------|
| **CLAUDE.md** | セッション開始・全リクエスト | 毎リクエスト（内容全体） |
| **Skills** | 開始時に説明文のみ、使用時にフル | 低（説明文のみ常時）|
| **MCP サーバー** | 開始時にツール名のみ、使用時にフルスキーマ | 使用するまで低 |
| **Code Intelligence** | ファイル編集後・シンボル参照時 | 低（ファイル読み込みを削減） |
| **Subagents** | スポーン時 | 独立（メインセッションから分離） |
| **Hooks** | イベント発火時 | ゼロ（出力を返さない限り） |

#### `disable-model-invocation: true` ― Skills のコンテキストコストをゼロに

```yaml
# .claude/skills/deploy/SKILL.md
---
name: deploy
description: Run deployment workflow
disable-model-invocation: true
---
手動で /deploy と入力したときだけ実行。Claude が自律的に使うことはない。
```

デフォルトでは、すべての Skills の説明文がセッション開始時に読み込まれる。`disable-model-invocation: true` を設定すると、説明文の読み込みが完全にスキップされ、コンテキストコストがゼロになる。副作用のあるコマンド（デプロイ・DB マイグレーション等）には必須。

#### `skillOverrides` ― ファイルを編集せず可視性を変更

```json
{
  "skillOverrides": {
    "deploy": { "disableModelInvocation": true },
    "db-migrate": { "disableModelInvocation": true }
  }
}
```

スキルファイルを直接編集できない場合（プラグイン提供のスキル等）でも、`settings.json` の `skillOverrides` で同等の制御ができる。

**適用提案**:
- 副作用のある全スキル（deploy・migrate・release）に `disable-model-invocation: true` を追加
- チーム共有のプラグインスキルは `skillOverrides` でプロジェクト単位の可視性制御
- MCP サーバーは `/mcp` コマンドでトークンコストを確認し、未使用サーバーは都度切断

### CLAUDE.md 200行ガイドライン & 機能追加トリガー表（公式）

**発見内容**: 公式が CLAUDE.md の具体的な行数上限と「何をいつ追加するか」のトリガー表を明記した。

#### CLAUDE.md は 200 行以内が目標

> "Keep CLAUDE.md under 200 lines. If it's growing, move reference content to skills or split into `.claude/rules/` files."

200 行を超えたら:
1. **参照系の内容**（API仕様・スキーマ詳細）→ Skill に移す
2. **特定ファイル/ディレクトリにしか関係ないルール**→ `.claude/rules/` の `paths:` フロントマターで対象を限定

#### 機能追加のトリガー表（公式推奨）

| このトリガーが起きたら | 追加するもの |
|---------------------|------------|
| Claude が同じ規約・コマンドを **2回以上** 間違えた | **CLAUDE.md** に追記 |
| 同じプロンプトを **毎回** 入力している | **Skill** として保存 |
| 同じ手順書・プレイブックを **3回以上** 貼り付けた | **Skill** に変換 |
| ブラウザのタブからデータを **毎回コピー** している | **MCP サーバー** で接続 |
| シンボル定義を探すために **大量ファイルを読んでいる** | **Code Intelligence プラグイン** をインストール |
| 会話に不要な出力が **大量に流れ込む** サイドタスクがある | **Subagent** に委譲 |
| 何かを **毎回必ず** 実行させたい | **Hook** に書く |
| 別リポジトリでも **同じ設定が必要** になった | **Plugin** にパッケージ化 |

「繰り返しの修正コメントは CLAUDE.md の編集であり、チャットへの一回限りの指示ではない」という原則が公式に明文化された。

**適用提案**:
- 現在の CLAUDE.md を行数カウントし、200 行超なら Skills 分離を実施（`wc -l CLAUDE.md`）
- チームの「よく使うプロンプト」を集めて `.claude/skills/` に変換する
- 上記トリガー表をチームの Claude Code 運用ガイドに追記する

### Custom Statusline ― コンテキスト使用率をリアルタイム表示

**発見内容**: Claude Code の底部に表示されるステータスラインをカスタマイズする機能が整備されており、コンテキスト使用率・コスト・レート制限などを常時モニタリングできる。

#### セットアップ方法

```bash
# Claude に自然言語でステータスラインを生成させる
/statusline コンテキスト使用率をプログレスバーで表示し、コストと経過時間も表示して
```

手動で設定する場合は `settings.json` の `statusLine` にスクリプトパスを指定:

```json
{
  "statusLine": "~/.claude/scripts/statusline.sh"
}
```

#### 利用可能な JSON フィールド（stdin で受け取る）

| フィールド | 内容 |
|-----------|------|
| `used_percentage` | コンテキスト使用率（%） |
| `model` | 使用中のモデル名 |
| `cost_usd` | セッションの累計コスト（USD） |
| `duration_seconds` | セッション継続時間 |
| `git.branch` | 現在のブランチ名 |
| `git.status` | git 状態 |
| `rate_limits.five_hour` | 5時間ウィンドウのレート制限状況（v1.2.80+） |

#### 最小構成スクリプト例

```bash
#!/bin/bash
# ~/.claude/scripts/statusline.sh
input=$(cat)
pct=$(echo "$input" | jq -r '.used_percentage // 0')
cost=$(echo "$input" | jq -r '.cost_usd // 0 | . * 100 | round | . / 100')
branch=$(echo "$input" | jq -r '.git.branch // ""')

# 使用率に応じて色を変える
if (( $(echo "$pct > 80" | bc -l) )); then
  color="\033[31m"  # 赤
elif (( $(echo "$pct > 60" | bc -l) )); then
  color="\033[33m"  # 黄
else
  color="\033[32m"  # 緑
fi

echo -e "${color}ctx: ${pct}%\033[0m | \$${cost} | ${branch}"
```

**適用提案**:
- `/statusline` コマンドで Claude に生成させて `~/.claude/settings.json` に設定
- `used_percentage` が 70% を超えた時点で色を変えて `/compact` の判断基準に
- `rate_limits.five_hour` を表示してレート制限を事前に把握

### Code Intelligence プラグイン ― LSP 連携でファイル読み込みを削減

**発見内容**: Code Intelligence プラグインをインストールすることで、Claude がシンボル参照・型エラーを LSP 経由で取得でき、大量のファイル読み込みを置き換えられる。

#### 動作原理

- プラグインをインストールするまで LSP ツールは**非アクティブ**（ゼロコスト）
- インストール後、Claude がファイル編集後に型エラー・警告を自動取得
- シンボルの定義・参照箇所を `/jump-to-definition` 相当の精度で検索
- ファイル全体を読まずにシンボル情報を得るため、**ネットのコンテキスト使用量が下がる**ことがある

#### 適用すべきケース

| 状況 | 推奨 |
|------|------|
| TypeScript/Python/Go 等の型付き言語を使っている | Code Intelligence プラグインを導入 |
| Claude が grep でシンボルを大量検索している | プラグインがファイル読み込みを削減 |
| 大規模コードベースで grep が遅い・不正確 | LSP が精確なシンボルナビゲーションを提供 |

```bash
# プラグインマーケットプレイスで Code Intelligence を検索
/plugin
```

**適用提案**:
- TypeScript プロジェクトには `typescript-language-server` ベースのプラグインを導入
- 導入後は CLAUDE.md の「src/ ディレクトリ構造の説明」などの静的情報を削減可能

### 機能レイヤー規則 ― 複数スコープが共存する際の優先度

**発見内容**: 複数スコープ（managed/user/project/plugin）で同じ機能が定義されたとき、機能種別ごとに適用ルールが異なることが公式で明確化された。

#### スコープ別マージ規則

| 機能 | マージ方式 | 優先度 |
|------|-----------|--------|
| **CLAUDE.md** | **加算的**（全レベルが合算） | 競合時は具体的な方が優先 |
| **Skills** | **名前で上書き**（1つが勝つ） | managed > user > project > plugin |
| **Subagents** | **名前で上書き**（1つが勝つ） | managed > CLI flag > project > user > plugin |
| **MCP サーバー** | **名前で上書き**（1つが勝つ） | local > project > user |
| **Hooks** | **マージ**（全フックが発火） | 優先度なし・全員実行 |

#### 注意点

- **CLAUDE.md が加算的**なため、user/project 両方に CLAUDE.md があると両方が読まれる。矛盾する指示があっても Claude が判断（ルールの競合はできれば避ける）
- **Hooks はマージ**のため、user レベルと project レベルで同じイベントに複数フックがあると全て実行される。順序依存の処理は注意
- **Skills は上書き**のため、project の同名 skill が user の同名 skill を隠す。チームポリシーの強制に活用可能

**適用提案**:
- 組織共通の禁止事項（`rm -rf` ブロック等）は managed スコープの Hook に配置（上書き不可にするため）
- チーム共通の skills は `.claude/skills/` に配置し、個人カスタマイズは `~/.claude/skills/` で管理
- `~/.claude/CLAUDE.md` と `./CLAUDE.md` が矛盾しないよう定期的にレビューする

### サブエージェントとエージェントチームの使い分け詳細

**発見内容**: サブエージェントとエージェントチームの違いが公式に詳しく整理された。特に「いつ切り替えるか」の判断基準が明確化された。

#### 比較表（公式）

| 観点 | Subagent | Agent Team |
|------|---------|------------|
| コンテキスト | 独自ウィンドウ、結果のみ報告 | 完全独立セッション |
| 通信 | 呼び出し元にのみ結果を返す | チームメート間で直接通信 |
| 調整 | メインエージェントが全管理 | 共有タスクリストで自己調整 |
| 向いているタスク | 結果のみ重要な集中タスク | 議論・協調が必要な複雑な作業 |
| トークンコスト | 低（サマリーのみ） | 高（各インスタンスが独立） |

#### 移行判断ポイント

> "If you're running parallel subagents but hitting context limits, or if your subagents need to communicate with each other, agent teams are the natural next step."

- 並列サブエージェントでコンテキスト上限に当たる → Agent Teams へ
- サブエージェント同士が互いの結果を参照する必要がある → Agent Teams へ

#### サブエージェントのコンテキスト詳細（新情報）

| エージェント | CLAUDE.md 読み込み | Git Status |
|------------|-------------------|-----------|
| カスタム定義エージェント | **読み込む** | **読み込む** |
| 組み込み Explore エージェント | **省略** | **省略** |
| 組み込み Plan エージェント | **省略** | **省略** |

`skills:` フィールドに列挙したスキルはサブエージェント起動時に**完全プリロード**（メインの「必要時ロード」と異なる）:

```markdown
---
name: code-reviewer
description: セキュリティとパフォーマンスに特化したコードレビュー
tools: Read, Grep, Glob
skills:
  - security-patterns
  - performance-checklist
---
```

**適用提案**:
- 「調査して結果だけ欲しい」タスク → `"use a subagent to investigate..."`
- 「セキュリティ・パフォーマンス・テストを同時に並列レビュー」→ Agent Teams
- カスタムサブエージェントに `skills:` でドメイン知識を事前ロードし、探索時間を短縮

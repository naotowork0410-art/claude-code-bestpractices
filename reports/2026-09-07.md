# Claude Code ベスプラ調査レポート 2026-09-07

## 今週の新発見

今週は v2.1.252〜v2.1.263（2026-08-31〜09-06）の大量リリースから、前回レポート（v2.1.251）以降の新機能・変更点を整理した。

---

### モデル: Claude Fable 5.1 追加（v2.1.257）

**発見内容**: 新モデル Fable 5.1 が追加され、`fable` エイリアスが更新された。

| 項目 | 値 |
|------|-----|
| コンテキスト | 1M トークン |
| 入力コスト | $10 / Mtok |
| 出力コスト | $50 / Mtok |
| キャッシュリード | $0.25 / Mtok |

注意点:
- `/effort` の変更が Fable 5.1 でプロンプトキャッシュを無効化しなくなった（v2.1.260 修正）
- `model: fable` フロントマター指定時は `ANTHROPIC_DEFAULT_FABLE_MODEL` 環境変数の `[1m]` タグが正しく参照される（v2.1.260 修正済み）
- `/model` ピッカーで Bedrock・Vertex AI・LLM ゲートウェイのモデルに分かりやすい名前が表示されるようになった（v2.1.261）

**適用提案**:
```yaml
# .claude/agents/heavy-analysis.md
---
name: heavy-analysis
description: 長大なコードベース全体解析用エージェント
model: fable
experimental:
  cacheTtl: 7200
---
```
- `fable` は最大コンテキストが必要なモノレポ全体解析・巨大ログ分析に使用
- コスト単価が高いため `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` で他エージェントは Sonnet/Haiku を強制する運用と組み合わせる

### 新コマンド: `/diff`（v2.1.260）

**発見内容**: `/diff` コマンドでフルスクリーンの差分パネルを開き、Claude が編集中の未コミット変更を視覚的に確認できるようになった。

```bash
# Claude 作業中でも随時実行可能
/diff
```

**適用提案**:
- 大規模リファクタリングや複数ファイル変更時に `/diff` でドリフトを確認しながら作業
- `--permission-prompts none`（v2.1.259 追加）と組み合わせた無人 CI 環境では `/diff` を PostToolUse フックから呼び出してログ保存

---

### 新コマンド: `/skill-doctor`（v2.1.261）

**発見内容**: ロード済みスキルのうち未使用のものとそのコンテキストコストを一覧表示する診断コマンドが追加された。

```bash
/skill-doctor
# 出力例:
# Unused skills (context cost):
#   heavy-web-scraper: 2,400 tokens
#   legacy-migration: 1,800 tokens
# Total wasted context: 4,200 tokens
```

**適用提案**:
- 月1回 `/skill-doctor` を実行し、コンテキストを消費しているが使われていないスキルを削除または `user-invocable: false` に変更
- `disableBundledSkills: true` との組み合わせで不要な組み込みスキルも除去し、実効コンテキスト予算を確保

### settings.json 新項目: 出力サイズ上限（v2.1.261）

**発見内容**: Bash コマンドとバックグラウンドタスクの出力をファイル保存せずインラインで受け取れる上限を設定できるようになった。

```json
// ~/.claude/settings.json
{
  "bashOutputMaxChars": 65536,
  "taskOutputMaxChars": 65536
}
```

デフォルト値は約 16K 文字（上限は 128K）。大きなテスト出力やビルドログをインラインで受け取りたい場合に有効。

**適用提案**:
- 長いテストスイートの出力を Claude にそのまま見せたい場合は `bashOutputMaxChars: 131072`（128K）に設定
- ただしコンテキスト消費が増加するため、コンパクションが早まる点に注意。`CLAUDE_AUTOCOMPACT_PCT_OVERRIDE: "70"` と組み合わせてバランスを取る

---

### settings.json 新項目: 時刻フォーマット制御（v2.1.257）

**発見内容**: 表示時刻のフォーマットとタイムゾーンを設定できるようになった。

```json
// ~/.claude/settings.json
{
  "timeFormat": "24-hour-utc",   // "12-hour" | "24-hour" | "24-hour-utc" | strftime
  "timeZone": "Asia/Tokyo"
}
```

**適用提案**:
- グローバルチームや Routines ログ分析では `"timeFormat": "24-hour-utc"` を推奨
- ステータスラインに時刻を表示する場合、`timeZone` で日本時間に固定してログとの整合性を確保

### 権限管理強化: `--permission-prompts none`（v2.1.259）

**発見内容**: 権限プロンプトが出る操作をすべて自動で拒否するフラグが追加された。

```bash
# プロンプトが出る操作は全て拒否（完全無人実行）
claude --permission-prompts none -p "Run tests and report results"

# 既存の --restricted と組み合わせ（コマンドツール除去 + プロンプト拒否）
claude --restricted --permission-prompts none \
  -p "Review src/ and suggest improvements" --output-format json
```

**適用提案**:
- CI/CD パイプラインでは `--restricted --permission-prompts none` の組み合わせがデフォルト
- `allowedTools` で必要なツールだけを明示した上で適用すると最安全

### MCP 強化: `managedMcpServers`（v2.1.259）

**発見内容**: 組織管理者が HTTP/SSE MCP サーバーを全ユーザーに自動配布できる `managedMcpServers` 設定が追加された。

```json
// /etc/claude-code/managed-settings.d/10-mcp.json（組織管理設定）
{
  "managedMcpServers": {
    "company-github": {
      "type": "http",
      "url": "https://mcp.company.internal/github",
      "auth": { "type": "oauth2", "clientId": "..." }
    },
    "company-jira": {
      "type": "http",
      "url": "https://mcp.company.internal/jira",
      "auth": { "type": "bearer", "tokenEnvVar": "JIRA_TOKEN" }
    }
  }
}
```

注意: `allowedMcpServers` は今バージョンからユーザー追加サーバーのみを制御し、managed サーバーには影響しない（v2.1.259 変更）。

**適用提案**:
- 社内 MCP サーバーを `managedMcpServers` に移行し、ユーザーが `.mcp.json` を管理する必要をなくす
- ユーザー側の `.mcp.json` は個人用ツール（ローカル filesystem サーバー等）のみに限定して衝突を防ぐ

### プロンプトキャッシュ診断: `/cost` 拡張（v2.1.260）

**発見内容**: `/cost` コマンドとステータスラインにプロンプトキャッシュミスの原因が表示されるようになった。

```
/cost
───────────────────────────────────────
Prompt cache: 85% hit (last turn: miss)
Cache miss reason: OAuth token refresh invalidated cache
Estimated savings: $0.42 today
───────────────────────────────────────
```

**適用提案**:
- `/cost` でキャッシュミス理由を確認し、OAuth 更新のタイミングや CLAUDE.md の変更頻度を見直す
- ステータスラインに `{{ cache_hit_rate }}` を追加して常時モニタリング:

```json
// ~/.claude/settings.json
{
  "statusLine": "{{ cache_hit_rate }}cache | {{ rate_limits.spend_limit }} | {{ context_pct }}%ctx"
}
```

### エージェント強化: CLAUDE_CODE_SUBAGENT_MODEL_FORCE（v2.1.257）

**発見内容**: `CLAUDE_CODE_SUBAGENT_MODEL` との違いとして、`CLAUDE_CODE_SUBAGENT_MODEL_FORCE` はフロントマターの `model:` 指定を上書きしてすべてのサブエージェントに強制適用する。

```bash
# 全サブエージェントを Haiku に強制（フロントマター model: 指定も無視）
export CLAUDE_CODE_SUBAGENT_MODEL_FORCE=claude-haiku-4-5-20251001

# Routines の場合は .envrc または cron 設定に追加
```

**適用提案**:
- コスト重視の CI 環境では `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=claude-haiku-4-5-20251001` をデフォルトに
- 品質重視の本番レビューでは `CLAUDE_CODE_SUBAGENT_MODEL=claude-sonnet-5`（強制なし）で、重要なエージェントだけ `model: opus` を指定する運用が適切

### セキュリティ: Auto Mode 封じ込めルール追加（v2.1.257）

**発見内容**: Auto mode に AWS 等のメタデータエンドポイントへのアクセスと クロステナント到達を自動ブロックするルールが追加された。

```
ブロック対象（自動）:
- http://169.254.169.254/  (IMDSv1 credential endpoint)
- http://[fd00:ec2::254]/  (IMDSv2)
- クロステナントAPIアクセス
```

**適用提案**:
- `sandbox.network.strictAllowlist` との二重防御でクラウド環境でのリスクをさらに低減
- `/permissions` の Auto mode タブ（v2.1.259 追加）で封じ込めルールを定期的に確認

---

### サブコマンド強化: `--append-subagent-system-prompt-file`（v2.1.261）

**発見内容**: 大きなサブエージェント用システムプロンプトをファイルから読み込めるようになった。

```bash
# ファイルから読み込み（--append-system-prompt でのインライン指定が不要に）
claude --append-subagent-system-prompt-file ~/.claude/subagent-base-instructions.txt \
  -p "Analyze the codebase"
```

**適用提案**:
- 長い共通サブエージェント指示（セキュリティルール、コーディング規約等）を `~/.claude/subagent-base-instructions.txt` に切り出し、各プロジェクトの `.envrc` や Routine 設定で参照
- CLAUDE.md の重複記述を削除し実効トークン予算を確保

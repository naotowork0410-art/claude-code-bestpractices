# Claude Code ベスプラ調査レポート 2026-09-14

## 今週の新発見

今週は v2.1.264〜v2.1.270（2026-09-07〜09-12）の変更を中心に整理した。
前週レポート（v2.1.263）以降の新機能・設定・修正を対象とする。

### プラグイン評価: `claude plugin eval`（v2.1.269）

**発見内容**: プラグインの eval スイートを Claude Code に対して実行し、スコア付きの再現可能な結果（JSON + HTML レポート）を生成する新コマンドが追加された。

```bash
# eval スイートを実行
claude plugin eval --help

# プロジェクト内のプラグインを評価
claude plugin eval --plugin-dir ./.claude-plugin

# JSON 出力でスコアを取得
claude plugin eval --output-format json | jq '.score'
```

**適用提案**:
- `.claude-plugin/evals/` 配下に eval ケースを作成し、CI で `claude plugin eval --output-format json` を定期実行
- スコアが閾値を下回ったら `--json` の `score` フィールドで CI を失敗させる
- `/skill-doctor` と組み合わせてスキルの品質と消費トークンを同時に管理

### settings.json 新項目: `bashEditDiffEnabled`（v2.1.269）

**発見内容**: Bash コマンドがファイルを変更した際、ツール結果にそのファイルの差分を自動添付する設定が追加された。これにより Claude が Bash 経由の変更を即座に把握できる。

```json
// ~/.claude/settings.json
{
  "bashEditDiffEnabled": true
}
```

**適用提案**:
- `sed -i` / `awk` / `perl -pi` のようなインプレース書き換えを多用するプロジェクトで有効化
- Bash でファイルを生成するビルドスクリプト実行後の意図しない変更を Claude に即認識させ、差し戻し判断の精度を向上
- `PostToolUse` フックと組み合わせて差分をログに記録する必要性が減少

### VSCode/IDE 統合大幅強化（v2.1.268〜v2.1.269）

**発見内容**: VSCode 拡張に以下の UI が追加され、ターミナル操作不要でフル設定管理が可能になった。

| 新機能 | 内容 |
|--------|------|
| **Agent Map** | サブエージェントごとのカード表示・個別停止・読み取り専用トランスクリプト |
| **Hooks Dialog** | user / project / local 設定のフック一覧・管理 |
| **Permission Rules Dialog** | 全スコープの権限ルール一覧表示・編集 |
| **MCP Servers Dialog** | サーバーの追加・削除フォーム（ターミナルセットアップ不要に） |
| **Focus View** | ツールコールの running/failed/done 表示・サブエージェントタスクリスト |
| **Archive Session** | 右クリックメニューからセッションをアーカイブ（Unarchive アイコン付き） |

**適用提案**:
- VSCode を使う場合、フック定義は Hooks Dialog から管理し JSON 直書きエラーを防ぐ
- Agent Map でサブエージェントの進捗を監視し、ハングしているエージェントを個別に停止可能
- MCP Servers Dialog で `.mcp.json` 手動編集なしに MCP サーバーを追加・削除

### OTEL メトリクス: `OTEL_METRICS_INCLUDE_REPOSITORY`（v2.1.269）

**発見内容**: OpenTelemetry メトリクスにリポジトリ情報（`vcs.*` 属性）をタグ付けする環境変数が追加された。`OTEL_LOG_TOOL_DETAILS` と合わせると、コミットイベントに `vcs.ref.head.*` も付く。

```bash
# .envrc や CI 設定に追加
export OTEL_METRICS_INCLUDE_REPOSITORY=1
export OTEL_LOG_TOOL_DETAILS=1

# Grafana/Datadog 側でリポジトリ別コスト・使用量を可視化
```

**適用提案**:
- モノレポ環境でリポジトリ別の Claude Code 使用コストを OTEL バックエンドで分離集計
- `vcs.ref.head.*` でブランチ別の使用量を分析し、コスト爆発したブランチを特定
- `CLAUDE_CODE_GATEWAY_MODEL_DISCOVERY_TIMEOUT_MS`（デフォルト 3000ms）を LLM ゲートウェイのレイテンシに合わせて調整

### ワークフロー並列数制御: `CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS`（v2.1.269）

**発見内容**: Workflow ツールの1実行あたりの同時エージェント数上限を 1〜256 の範囲で設定可能になった（デフォルトは `workflowSizeGuideline` に依存）。

```bash
# 推論バウンドの大規模ファンアウトでスループット向上
export CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS=64

# CI リソース節約のため制限
export CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS=8
```

**適用提案**:
- ファイル並列変換・大規模コードレビューなど推論バウンドのタスクには 32〜64 に引き上げ
- API レート制限が厳しい環境では 4〜8 に絞りスロットリングを防止
- `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`（通常セッション）との二重管理に注意（Workflow は別カウント）

### WebFetch ハング対策: `CLAUDE_CODE_WEBFETCH_DEADLINE_MS`（v2.1.268）

**発見内容**: WebFetch がレスポンスを開き続けるサーバーで無限ハングする問題が修正され、デフォルト 300 秒タイムアウトが設定された。環境変数で上書き可能。

```bash
# 短いタイムアウト（60秒）でハング早期検出
export CLAUDE_CODE_WEBFETCH_DEADLINE_MS=60000

# 大容量ドキュメントフェッチ用に延長（10分）
export CLAUDE_CODE_WEBFETCH_DEADLINE_MS=600000
```

**適用提案**:
- Web スクレイピングを多用するワークフローでは `60000`（60秒）に短縮してエラーを早期検出
- 大きな PDF や S3 直接ダウンロードがある場合は適宜延長
- CI 環境では `120000`（2分）程度が安全なデフォルト

### Claude Tag (Slack): Routines の既存スレッド返信（v2.1.269）

**発見内容**: Slack の Claude Tag において、Routine の実行結果を毎回新規トップレベルメッセージとして投稿するのではなく、既存スレッドに返信できるようになった。

**適用提案**:
- 日次・週次 Routine は同一スレッドに返信させ、Slack チャンネルのノイズを削減
- スレッド ID を Routine 設定に紐付け、1週間分の結果を1スレッドで追跡
- このレポート自体も Routine で Slack に集約配信する場合は既存スレッド返信モードを活用

### バックグラウンドエージェント状態報告: `CLAUDE_CODE_BG_TASKS_REPORT_RUNNING`（v2.1.269）

**発見内容**: リモートセッションがバックグラウンドエージェント実行中に「入力待ち」と誤報告するバグが修正された。旧動作に戻す場合は環境変数で制御できる。

```bash
# 旧動作（修正前の挙動）に戻す場合のみ使用
export CLAUDE_CODE_BG_TASKS_REPORT_RUNNING=0
```

**適用提案**:
- Remote Control / Routines でのバックグラウンドエージェント監視精度が向上
- ListAgents / Agent Map でエージェント状態を取得するモニタリングスクリプトは修正後の正確な状態を使えるようになった

### `/output-style` のヘッドレス対応（v2.1.269）

**発見内容**: `/output-style [name]` コマンドで Output Style を一覧表示・切り替えられるようになった。これが **Remote Control やクラウド/ヘッドレスセッションでも動作**するようになった。

```bash
# ヘッドレスセッションで出力スタイルを切り替え
/output-style concise

# 利用可能なスタイル一覧
/output-style
```

**適用提案**:
- Routines（自動実行）では `/output-style concise` でレポートのノイズを削減
- Remote Control 経由のモバイル操作時は `/output-style concise` でスクロール量を削減
- カスタム Output Style (`.claude/output-styles/`) を Routine 用に作成し、構造化出力を強制

### hooks ベストプラクティス（2026年最新定説）

**発見内容**: 2026年のフックコミュニティで定着したルールが以下に収束している。

| 原則 | 内容 |
|------|------|
| **影響レベル判断基準** | 「無視されたら本番インシデント」→ hook / 「無視されたら軽微な問題」→ CLAUDE.md |
| **PreToolUse の権威性** | PreToolUse の exit 2 はbypassPermissions / --dangerously-skip-permissions を**上回ってブロック**する |
| **レイテンシ上限** | PreToolUse ホットパスは 100ms 以内・PostToolUse は 5s 以内 |
| **重い処理の置き場所** | フルテストスイート・フル lint は SessionEnd またはCI（毎 Edit ではない） |
| **フック種別と用途** | PostToolUse から始める（非ブロッキング）→ 安定したら PreToolUse に昇格 |

**適用提案**:
```json
// ~/.claude/settings.json - Hooks を PostToolUse から始めるテンプレート
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{
          "type": "command",
          "command": "prettier --write ${tool.input.file_path} 2>/dev/null; exit 0"
        }]
      }
    ],
    "Stop": [
      {
        "hooks": [{
          "type": "command",
          "command": "npm test -- --silent 2>&1 | tail -5"
        }]
      }
    ]
  }
}
```

### 権限ルールのバグ修正: `!` プレフィックスのスコープ限定（v2.1.269）

**発見内容**: `deny`/`ask` ルールが `!` で始まる場合、そのルールが定義されたスコープ外（別の settings ファイル）にも適用されるバグが修正された。

**適用提案**:
- `!` プレフィックスルールを使っている場合、修正後の動作を検証する（期待通りのスコープで動いているか確認）
- `managed-settings.d/` に `!` ルールを置いている組織は全ユーザーへの影響を再評価

# Claude Code ベスプラ調査レポート 2026-09-21

## 今週の新発見

今週は v2.1.271〜v2.1.278（2026-09-14〜09-19）の変更を中心に整理した。
前週レポート（v2.1.269 まで）以降の新機能・設定・修正を対象とする。

---

### AGENTS.md サポート: CLAUDE.md 不要プロジェクトへの対応（v2.1.277/278）

**発見内容**: CLAUDE.md が存在しないプロジェクトで、代わりに `AGENTS.md` を読み込む機能が追加された。これにより Cursor・Copilot など他 AI ツールとの設定ファイル共存がしやすくなった。`/config` の「Project instructions」から直接編集可能（Bedrock/Vertex/Foundry は未対応）。

```bash
# CLAUDE.md の存在しないリポジトリで自動認識される
# AGENTS.md に通常の CLAUDE.md 相当の内容を記述
cat AGENTS.md
# => プロジェクト概要・命名規則・テストコマンド等

# /config から編集
/config  # → "Project instructions" タブで AGENTS.md の内容を確認・編集
```

**適用提案**:
- 他 AI ツールとの共存リポジトリでは `AGENTS.md` に統一し、`@AGENTS.md` インポートで CLAUDE.md からも参照
- CLAUDE.md を持つプロジェクトでは従来通り優先される（CLAUDE.md が存在する場合は AGENTS.md は読まれない）
- モノレポで一部サブプロジェクトが CLAUDE.md を持たない場合に活用

### Auto mode サーバーサイドクラシファイア: クラシファイアコスト不要に（v2.1.278）

**発見内容**: Claude API・Enterprise・Bedrock/Vertex/Foundry/ゲートウェイユーザー向けに、auto mode のクラシファイアがサーバーサイドに変更された。これまでのクライアントサイドクラシファイアによる追加課金が不要になる。`/status` に「Auto mode server」行が追加され、どこでクラシファイアが動いているか確認できる。

```bash
# 現在のクラシファイア場所を確認
/status
# → "Auto mode server: server (Anthropic)" などが表示

# Bedrock/Vertex/Foundry ではサーバーサイドをオプトイン
export CLAUDE_CODE_AUTO_MODE_SERVER=1  # gateways でサーバーサイドに切り替え

# API/Enterprise でローカルクラシファイアに戻したい場合
export CLAUDE_CODE_AUTO_MODE_SERVER=0
```

**適用提案**:
- API ユーザーは設定変更なしでクラシファイアコスト削減の恩恵を受けられる
- Bedrock/Vertex ユーザーが `CLAUDE_CODE_AUTO_MODE_SERVER=1` を設定するとレイテンシ削減
- `/status` でクラシファイア動作場所をモニタリングする確認コマンドとして活用

### skills/plugins の claude.ai アカウント同期（v2.1.275）

**発見内容**: claude.ai アカウントでインストール・有効化したスキルおよびプラグインが、ターミナルセッションに自動同期されるようになった。Web UI で管理した設定を CLI でも即時利用可能になる。不要な場合は settings.json で個別に無効化できる。

```json
// ~/.claude/settings.json
{
  "syncClaudeAiSkills": false,    // スキルの同期を無効化
  "syncClaudeAiPlugins": false    // プラグインの同期を無効化
}
```

**適用提案**:
- Web UI（claude.ai）でスキルを管理し、CLI でも同一スキルを利用する統一ワークフローが実現
- 大量のスキルをインストールしているとコンテキストコストが上昇するため、`/skill-doctor` で定期的に不使用スキルを確認・無効化
- CI/自動化環境では `syncClaudeAiSkills: false` でスキルセットを固定し再現性を担保

### `Ctrl+Enter` 送信ショートカット: 割り込み即時送信（v2.1.275）

**発見内容**: `Ctrl+Enter`（または `Ctrl+X Ctrl+S`）で、現在のターンを中断してキューにたまったメッセージをまとめて即時送信できるようになった。

```bash
# Claude が長時間作業中に方向修正したい場合
# 1. プロンプトを入力（まだ送信しない）
# 2. Ctrl+Enter で現在のターンを中断して即時送信
```

**適用提案**:
- 長時間の並列エージェント処理中に方向修正や追加指示を割り込ませる際に活用
- Enter だけでは「中断＋送信」ではなく「次ターンで送信」になるケースとの使い分けを意識
- Remote Control や Web セッションでキューに積まれたメッセージを一括送信する際に有効

### MCP 起動待機制御: `CLAUDE_CODE_MCP_STARTUP_WAIT_MS`（v2.1.274/275）

**発見内容**: 非インタラクティブセッション（`-p` フラグ）の初回ターンで MCP サーバーの起動完了を待つ時間を制御する環境変数が追加された。`0` を設定すると待機せず即座にターンを開始する（MCP ツールは後で接続後に利用可能になる）。

```bash
# CI 環境で MCP 起動を待たずに即座に開始
export CLAUDE_CODE_MCP_STARTUP_WAIT_MS=0

# 最大 5 秒まで待機（デフォルトより短縮）
export CLAUDE_CODE_MCP_STARTUP_WAIT_MS=5000

# 起動が遅い MCP サーバーに対して長め待機
export CLAUDE_CODE_MCP_STARTUP_WAIT_MS=30000
```

**適用提案**:
- CI で MCP サーバーを使わないパイプラインでは `0` を設定してスタートアップを高速化
- `github` MCP のような起動が速いサーバーには `5000` 程度に短縮
- 社内プロキシ経由の重い MCP サーバーでは `30000` 以上に設定して接続タイムアウトを防止

### Gateway ヒントヘッダー: ルーティング最適化（v2.1.273）

**発見内容**: `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1` を設定すると、Claude Code がゲートウェイに対してリクエスト種別のヒント情報を HTTP ヘッダーで送信するようになった。ゲートウェイ側がこれを利用してルーティングやロードバランシングを最適化できる。

```bash
# ゲートウェイ環境に設定（.envrc または CI）
export CLAUDE_CODE_GATEWAY_HINT_HEADERS=1

# 付与されるヘッダー:
# x-claude-code-request-class     リクエスト種別（llm/tool/subagent 等）
# x-claude-code-agent-type        エージェントタイプ（main/subagent/fork）
# x-claude-code-prev-tool-durations  前回ツール呼び出しの実行時間
# x-claude-code-compaction        コンパクション状態
# x-claude-code-context-compacted  コンテキスト圧縮フラグ
```

**適用提案**:
- エンタープライズゲートウェイ管理者: `x-claude-code-request-class` でメインセッションとサブエージェントのトラフィックを分離してロードバランシング
- `x-claude-code-prev-tool-durations` でツール実行時間に基づくアダプティブルーティングを実装
- Datadog/Grafana でヘッダーを記録し Claude Code ワークロードを可視化

### `omitClaudeMd` エージェント設定: 軽量サブエージェント（v2.1.271）

**発見内容**: カスタムエージェントおよびプラグインのサブエージェントに `omitClaudeMd: true` を設定すると、ユーザー・プロジェクト・ローカルの CLAUDE.md ファイルを読み込まずにサブエージェントが起動するようになった。特化タスク向けの軽量エージェントに有効。

```markdown
---
# .claude/agents/fast-reviewer.md
model: haiku
omitClaudeMd: true
description: "高速コードレビュー専用エージェント（CLAUDE.md を読まない）"
---

あなたは高速コードレビュー専用エージェントです。
変更差分のみを確認し、バグ・セキュリティ・パフォーマンス問題を報告してください。
```

**適用提案**:
- ルーティング・分類・要約など純粋な処理タスクには `omitClaudeMd: true` でコンテキスト消費を最小化
- Writer/Reviewer パターンの Reviewer エージェントに設定し、プロジェクト固有バイアスを排除
- ファンアウト並列エージェント（大量ファイル処理）に適用しトークンコストを削減

### `maxEffortLevel` 設定: モデル別エフォートキャップ（v2.1.263 週 / Week 37）

**発見内容**: `maxEffortLevel` を最上位レベルまたは `modelSettings` 配下のモデル別に設定することで、任意のプロバイダー（Bedrock・Vertex・Foundry を含む）でのエフォートレベルに上限を設定できる。設定値より高いレベルを指定するとキャップ値で実行される。

```json
// ~/.claude/settings.json
{
  "maxEffortLevel": "high",          // 全体上限: max/xhigh を指定しても high で実行

  "modelSettings": {
    "claude-haiku-4-5": {
      "maxEffortLevel": "medium"     // Haiku は medium を上限に
    },
    "claude-sonnet-5": {
      "maxEffortLevel": "xhigh"      // Sonnet 5 は xhigh まで許可
    }
  }
}
```

**適用提案**:
- コスト管理: 本番 CI では `maxEffortLevel: "high"` でエフォルト暴走を防止
- モデル別設定: 安価な Haiku を呼ぶ定型タスクは `medium` にキャップし推論コストを抑制
- 組織の `managed-settings.d/20-cost-control.json` でエンタープライズ全体に適用

### OTEL 強化: エフォート属性・マネージド設定イベント（v2.1.274）

**発見内容**: OpenTelemetry スパンへの情報付与が強化された。`claude_code.llm_request` スパンに `effort` 属性が追加され、モデルリクエストのエフォートレベルをトレースで追跡できる。また `OTEL_LOG_MANAGED_SETTINGS=1` でマネージド設定の読み込みをオブザーバビリティ基盤に記録できる。

```bash
# .envrc に追加
export OTEL_LOG_MANAGED_SETTINGS=1     # マネージド設定のソース・ポリシー状態を記録
export OTEL_METRICS_INCLUDE_REPOSITORY=1  # vcs.* 属性でリポジトリ別集計（前週追加）

# claude_code.llm_request スパンで effort 属性を確認
# → Grafana/Datadog でモデル × エフォートレベル × コストのクロス集計が可能
```

**適用提案**:
- マネージド設定の配布状況を OTEL バックエンドで可視化し、設定変更のロールアウト状況を追跡
- `effort` 属性で高エフォートリクエストが多発しているチームを特定しコスト最適化を提案
- `claude_code.managed_settings_resolved` イベントをアラートソースとして使い、ポリシー変更を即座に検知

### VSCode 新ダイアログ: Hooks・Permission・Memory（v2.1.275）

**発見内容**: VSCode 拡張に3つの新ダイアログが追加された。これにより settings.json の手動編集なしにフック・権限・メモリを管理できる。

| ダイアログ | 機能 |
|-----------|------|
| **Hooks Dialog** | ユーザー/プロジェクト/ローカルスコープのフック一覧・追加・削除 |
| **Permission Rules Dialog** | 全スコープの権限ルール一覧・編集（allow/deny/ask） |
| **Memory Dialog** | メモリファイルの閲覧・編集・削除（`~/.claude/memory/` 管理） |

```bash
# コマンドメニューから呼び出し
# → "Customize" セクション → "Hooks" / "Permissions" / "Memory"

# または typed commands
/hooks
/memory
```

**適用提案**:
- Memory Dialog でセッション蓄積メモリの肥大化を定期確認・クリーニング（コンテキスト削減）
- Permission Rules Dialog で `ask` ルール（3ティア権限）を視覚的に管理
- フックの `if` フィールドによる細粒度フィルタリングを GUI で設定（JSON 直書き不要に）

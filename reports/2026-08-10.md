# Claude Code ベストプラクティス調査レポート 2026-08-10

## 今週の新発見

### クロスセッション エージェント通信（v2.1.224/225）

**発見内容**: `SendMessage` と `ListAgents` がクロスマシン対応になった（v2.1.225）。同一アカウントの別マシン・別セッションで動く Claude エージェントに名前を使ってメッセージを送信できる。マルチマシン CI パイプラインや、Web/Mobile セッションからローカルセッションへの指示転送が可能になる。

新設された設定項目:

```json
// ~/.claude/settings.json または .claude/settings.json
{
  "crossSessionInbound": true,   // 他セッションからの SendMessage を受け入れる
  "dialogExpiry": 120            // 入力待ちダイアログの自動タイムアウト（秒）
}
```

**自己ホスト環境（v2.1.224）**:

```bash
# Team/Enterprise プランで自社インフラ上でセッションを実行
claude self-hosted-runner --base-dir /var/claude-runner
```

Claude Code Web/Mobile/Desktop セッションを自社マシンまたはコンテナ上で動かせる。社内ネットワークへのアクセス・コンプライアンス制御・カスタムツール統合が要件の場合に有効。

**適用提案**:
- CI 環境や Routines で長時間エージェントを使う場合、`crossSessionInbound: true` で監視エージェントからの停止指示を受け取れるようにする
- `dialogExpiry` を非インタラクティブ実行では短めに設定し（例: `30`）、入力待ちでハングしないようにする
- Team/Enterprise プランでは `claude self-hosted-runner` を評価し、内部 API やデータベースに直接アクセスできる環境を整備する

### セキュリティ強化: 多層防御パターン（v2.1.222/223/224）

**発見内容**: v2.1.222〜224 にかけてセキュリティ関連の変更が集中した。いくつかは破壊的な挙動修正も含む。

**重要な挙動変更（v2.1.222）**:
- `PreToolUse` の auto-allow フックが以前はツール制限を回避できていたが、**この抜け穴が修正された**。`PreToolUse` で自動承認を設定していた場合、`permissions.deny` で明示的に制限したツールも許可されてしまっていた。
- ワークトリー分離セッションから破壊的 git コマンド（`--force`, `reset --hard` 等）が実行できなくなった。
- Bash ツールのタブ文字・Unicode 隠蔽による権限バイパスが修正された（v2.1.223）。

**サンドボックス認証情報マスキング（v2.1.224）**:

```json
// .claude/settings.json
{
  "sandbox": {
    "credentials": {
      "extract": "Bearer ([A-Za-z0-9._-]+)",  // regex でトークンを抽出
      "onExtractNoMatch": "block",             // マッチしない場合はブロック
      "decode": "jwt",
      "maskClaims": ["sub", "email"],          // JWT クレームをマスク
      "awsPairs": true,                        // AWS キーペアをマスク
      "sigv4": true                            // AWS SigV4 署名を再署名
    }
  }
}
```

**マーケットプレイス ワイルドカード制御（v2.1.223）**:

```json
// managed-settings.d/10-marketplace-policy.json
{
  "strictKnownMarketplaces": ["anthropic/*", "trusted-org/*"],
  "blockedMarketplaces": ["unknown-vendor/*"]
}
```

`owner/*` 形式のワイルドカードが使えるようになり、組織単位での許可/拒否リストを一行で管理できる。

**セキュリティフック 4 本セット（コミュニティ推奨）**:

```json
// ~/.claude/settings.json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [{
          "type": "command",
          "command": "~/.claude/hooks/dangerous-actions-blocker.sh"
        }]
      }
    ]
  }
}
```

| フック名 | 役割 |
|--------|------|
| `dangerous-actions-blocker` | `rm -rf`・force-push・本番操作をブロック |
| `prompt-injection-detector` | CLAUDE.md やプロンプトへの注入パターンを検出 |
| `unicode-injection-scanner` | ゼロ幅文字・RTL オーバーライドをキャッチ |
| `output-secrets-scanner` | レスポンス内の API キー・トークンを検出 |

**適用提案**:
- `PreToolUse` auto-allow フックを使っている場合、`permissions.deny` との組み合わせ動作を再検証する（v2.1.222 以降は意図通りに制限が機能するようになった）
- `sandbox.credentials` 設定で JWT や AWS 認証情報を自動マスキングし、ログやサブエージェント間の情報漏洩を防ぐ
- `strictKnownMarketplaces: ["自社org/*"]` を `managed-settings.d/` のポリシーファイルに追加してプラグイン供給元を制限する

### プラグインシステム強化: HTTPS zip インストール + 即時有効化（v2.1.222/224）

**発見内容**: プラグインのインストール方法とライフサイクルが改善された。

**HTTPS zip ソースからのインストール（v2.1.224）**:

```bash
# SHA-256 ピニングで信頼性を担保しながらインストール
/plugin install https://example.com/my-plugin.zip --sha256 abc123...
```

プライベートレジストリや社内ネットワーク上のプラグインを、マーケットプレイスを経由せずに安全に配布できる。

**即時有効化（v2.1.222）**:
- プラグインが安全と判定された場合、`/reload-plugins` なしで即時に有効化される
- プラグイン内の `skills` パスに `"."` を指定可能（プラグインルートを直接スキルディレクトリとして扱える）

```json
// .claude-plugin/plugin.json
{
  "name": "my-tools",
  "skills": "."   // プラグインルートをスキルディレクトリとして使用
}
```

**適用提案**:
- 社内共有のスキルセットやフックをプラグインとしてパッケージ化し、HTTPS zip 配布で `/plugin install <URL> --sha256 <hash>` によるインストールを標準化する
- `skills: "."` を使うとプラグインの構造を簡素化できる（スキル専用サブディレクトリが不要になる）

### サブエージェント スケーリング制御の刷新（v2.1.217/224）

**発見内容**: 2 つの設定変更が組み合わさって、長時間・大規模エージェントタスクの扱いが変わった。

**200 サブエージェント上限の撤廃（v2.1.224）**:

以前はセッションあたり最大 200 サブエージェントしか起動できなかったが、この上限が**削除された**。長時間 Routine タスクや大規模コードベース移行でセッション途中に打ち切られる問題が解消される。

**同時実行上限の追加（v2.1.217）**:

```bash
# 同時実行サブエージェント数を制限（デフォルト 20）
export CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS=10
```

総数の上限は撤廃しつつ、同時実行数で過負荷を防ぐ設計に変更された。

**コンテキスト圧力しきい値（コミュニティ定説）**:

| 使用率 | 状態 | 推奨アクション |
|-------|------|--------------|
| 0–50% | 正常 | 自由に作業 |
| 50–70% | 注意 | コンテキストを意識し始める |
| 70–90% | 劣化 | `/compact` を実行する |
| 90%+ | 危険 | `/clear` が必須、作業を失わないよう先にコミット |

特に 85% 超で幻覚（hallucination）が増加するという実測値が複数のコミュニティレポートで確認されている。

**適用提案**:
- CI/Routines でのサブエージェント過負荷防止には `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS=5〜10` を設定する（総数上限の撤廃後、同時実行制御がより重要になった）
- 70% コンテキスト使用率に達したら即座に `/compact 変更ファイルリストとテストコマンドを保持` を実行するルールを CLAUDE.md に明記する

### VSCode 統合: Focus View + クラウドレビュー強化（v2.1.221/222）

**発見内容**: VSCode 拡張と `/code-review` コマンドが強化された。

**Focus View（v2.1.221）**:

```
Ctrl+Alt+F
```

VSCode の Claude Code パネルでツールアクティビティの要約ビューに切り替わる。長時間タスク中にサブエージェントの活動状況を俯瞰できる。

**クラウド深度レビュー（v2.1.222）**:

```
/code-review ultra
/review ultra     ← /review が /code-review のエイリアスになった
```

`ultra` オプションで非インタラクティブ対応のクラウドベース深度レビューが実行される。ローカルのコンテキストを消費せずに大規模差分を分析できる。

**`/teleport` ヒント（v2.1.223）**:

クラウドセッション（claude.ai/code）上でローカルで続けたい場合、ツールがヒントを表示するようになった。`/teleport` でクラウド→ローカル転送を即座に実行できる。

**適用提案**:
- PR レビュータスクでは `/code-review ultra` を使い、メインセッションのコンテキストを温存する
- VSCode ユーザーは `Ctrl+Alt+F` で Focus View を使い、バックグラウンドサブエージェントの動作を監視する
- `/review` も `/code-review` と同じコマンドとして使えるようになったため、スキルや CLAUDE.md の記述を `code-review` に統一する

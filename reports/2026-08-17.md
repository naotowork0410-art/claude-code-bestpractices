# Claude Code ベストプラクティス調査レポート 2026-08-17

## 今週の新発見

### サブエージェント: fork がデフォルト化（v2.1.232）

**発見内容**: v2.1.232 から `subagent_type: "fork"` がサブエージェントのデフォルト動作になった。フォークされたサブエージェントは親セッションの**全会話とプロンプトキャッシュ**を引き継ぐ。

変更前は新規サブエージェントが空のコンテキストで起動していたが、フォークデフォルト後は親の文脈を知った上で処理を開始できる。これにより「背景を説明してから委譲」という手順が不要になる。

追加の挙動変更:
- 非チームメートのサブエージェントはインタラクティブセッションでも**バックグラウンド実行がデフォルト**になった

オプトアウト方法:
```bash
export CLAUDE_CODE_FORK_SUBAGENT=0
```

**適用提案**:
- 従来のサブエージェント定義（`.claude/agents/<name>.md`）はそのまま動作するが、フォーク後は親コンテキストを持つため、過去に「親の文脈をプロンプトで再説明」していた箇所を削減できる
- バックグラウンドデフォルト化により、`/agents` ビューで進捗を確認する習慣を組み合わせること
- フォークが不要なシンプルなタスクでは `CLAUDE_CODE_FORK_SUBAGENT=0` を設定してメモリ使用量を最適化する

### クロスセッション通信: `@メンション` 構文（v2.1.232）

**発見内容**: プロンプトに `@セッション名` を書くだけで別の Claude セッションに `SendMessage` が届くようになった。`ListAgents` でセッション一覧を取得する手順が不要になり、自然な会話形式でセッション間通信ができる。

```
# セッション "backend-worker" に指示を送る例
@backend-worker 認証APIのテストが終わったら教えて
```

動作の詳細:
- 完全一致する live セッションが 1 つだけ存在する場合は**確認ダイアログなしで即配信**
- 複数マッチする場合のみ選択が求められる
- `/config` に「Dialog expiry」と「Messages from your other sessions (accept/hold/refuse)」の設定行が追加された

**適用提案**:
- マルチセッション Routine では、監視役セッションから `@worker-session` 形式で状況確認や停止指示を送れる
- `crossSessionInbound: true` と `allowedMarketplaces` を組み合わせ、受信許可を制御しておく
- セッション名に意味のある名前を付ける（`/rename`）ことで `@` メンションが使いやすくなる

### TodoツールがOpus 4.8 / Sonnet 5 以降で廃止（v2.1.233）

**発見内容**: `TaskCreate`・`TaskGet`・`TaskUpdate`・`TaskList`・`TodoWrite` が Opus 4.8、Sonnet 5、Fable 5、Mythos 5 以降のモデルでは**デフォルト無効**になった。

再有効化方法:
```bash
# 環境変数で再有効化
export CLAUDE_CODE_ENABLE_TODO_TOOLS=1
```

または settings.json:
```json
{
  "env": {
    "CLAUDE_CODE_ENABLE_TODO_TOOLS": "1"
  }
}
```

代替アプローチ（ツールを使わない場合）:
- Hooks の `Stop` イベントで進捗ログをファイルに書き出す
- CLAUDE.md に「作業前に TODO リストを `todo.md` に書き出す」ルールを明記する
- Skill として `task-tracking` スキルを作り、ファイルベースのタスク管理を統一する

**適用提案**:
- Routine や長時間エージェントタスクで TaskCreate に依存している場合は早急に `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` を設定するか、ファイルベースのタスク管理に移行する
- 新規プロジェクトでは Opus 4.8/Sonnet 5 以降を前提とし、タスク管理はファイルまたは `PostToolUse` フックで行う設計に変える

### デスクトップ Auto-continue チェックボックス（2026-08-14）

**発見内容**: Claude Code Desktop アプリに「**☑ Auto-continue when limits reset**」チェックボックスが追加された。使用制限（5時間枠・週次枠）がリセットされると、自動的にセッションを再開する。

重要な注意点:
- これは**制限の増加ではない**。5時間枠・週次枠の上限自体は変更なし
- **CLI にはまだ実装されていない**（デスクトップアプリ限定）
- CLI では `claude-auto-retry` 等のサードパーティ実装で代替可能

Routine や自動化タスクでの影響:
- Web/Mobile からのスケジュールタスクは Auto-continue の恩恵を受けられない（CLIベース）
- 長時間タスクはデスクトップアプリで実行するか、制限リセット後の再起動を Routine に組み込む

**適用提案**:
- 長時間の対話型タスク（コードベース移行、大規模リファクタリング等）はデスクトップアプリで実行し、Auto-continue を有効化する
- CLIベースの長時間タスクは `while` ループ + `claude --continue` で制限リセット後の再開を自動化する暫定対応が有効

### GitLab 統合の本格化（v2.1.232/233）

**発見内容**: GitHub 中心だった Claude Code の統合が GitLab にも本格的に拡張された。

**GitLab MR の worktree 対応（v2.1.233）**:
```bash
# GitLab MR URL で worktree を作成
claude --worktree https://gitlab.com/org/repo/-/merge_requests/42
```
`claude agents` ビューでは MR が `!42` の形式で表示される。

**GitLab トークン自動リダクション（v2.1.232）**:

以下のトークンプレフィックスが自動マスキングされる:
| プレフィックス | 用途 |
|------------|-----|
| `glrt-` | Runner registration |
| `gloas-` | OAuth application secret |
| `glptt-` | Pipeline trigger token |
| `glagent-` | Agent token |
| `glimt-` | Impersonation token |
| `glsoat-` | Service account token |
| `glft-` | Feature flag token |
| `glpat-` / `gldt-` | Personal/Deploy access token（完全リダクション）|

**GitLab プラグインマーケットプレイス対応（v2.1.232）**:
```bash
# bare GitLab URL からプラグインをインストール
/plugin install gitlab.com/myorg/mygroup/my-plugin
```
ネストされたサブグループもサポート。

**適用提案**:
- GitLab を使うチームは `glab` CLI を MCP サーバー経由で統合し、MR レビュー・CI 確認を Claude Code から直接行えるようにする
- `.env` などに GitLab トークンを含む場合、v2.1.232 以降では自動リダクションが機能するが、`sandbox.credentials` 設定で明示的な制御を追加すると二重の保護になる

### 新しい環境変数（v2.1.233）

**発見内容**: 2 つの新しい環境変数が追加された。

**`CLAUDE_CODE_TOOL_MEMORY_LIMIT`（Linux 向け）**:
```bash
# Bash ツールのメモリ使用量を cgroup で制限（Linux のみ）
export CLAUDE_CODE_TOOL_MEMORY_LIMIT="512M"
```
サンドボックス環境での Bash ツールのメモリ暴走を OS レベルで防止できる。CI パイプラインやマルチエージェント環境で有用。

**`CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS`**:
```bash
# WebFetch のセッション URL キャッシュの TTL を変更（デフォルト: 15分 = 900000ms）
export CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS=1800000  # 30分に延長
```
同一 URL を頻繁に fetch するスキルや Routine では TTL を延長してリクエスト数を削減できる。ドキュメント参照が多いタスクに有効。

**適用提案**:
- Linux CI 環境では `CLAUDE_CODE_TOOL_MEMORY_LIMIT=512M` を設定し、Bash ツールが過剰なメモリを消費してコンテナが kill されるのを防ぐ
- API ドキュメントや設定ファイルを繰り返し参照する Routine では `CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS` を 1800000（30分）程度に延ばしてコストと速度を改善する

### セキュリティ: Windows 複数の権限バイパスが修正（v2.1.232/233）

**発見内容**: Windows 環境での複数のセキュリティバイパスが修正された。

| 修正内容 | バージョン |
|--------|---------|
| PowerShell `$PSDefaultParameterValues` への変数書き込みによる権限バイパス | v2.1.232 |
| Windows Git Bash が Cygwin スタイルシンボリックリンクを辿ることによる権限バイパス | v2.1.232 |
| ネストされた git リポジトリが親ディレクトリの信頼を継承してしまう問題 | v2.1.232 |
| NT デバイスプレフィックス（`\??\`）付きパスが UNC 検証をバイパスする問題 | v2.1.233 |

**Windows ユーザーへの適用提案**:
- v2.1.232/233 に直ちにアップデートする（`npm update -g @anthropic-ai/claude-code`）
- Windows 環境でシンボリックリンクや PowerShell スクリプトを多用する場合、更新後に権限動作を再テストする
- `permissions.deny` のパスベースルールが Windows でも期待通りに機能することを確認する

### settings.json エイリアス追加（v2.1.232）

**発見内容**: マーケットプレイス制御の設定キーに友好的なエイリアスが追加された。

| 新しいエイリアス | 元のキー |
|------------|--------|
| `additionalMarketplaces` | `extraKnownMarketplaces` |
| `allowedMarketplaces` | `strictKnownMarketplaces` |

```json
// 旧（引き続き動作する）
{
  "strictKnownMarketplaces": ["anthropic/*", "myorg/*"]
}

// 新（より分かりやすい名前）
{
  "allowedMarketplaces": ["anthropic/*", "myorg/*"]
}
```

**適用提案**:
- 既存の設定はそのまま動作するが、新規設定ファイルでは `allowedMarketplaces` / `additionalMarketplaces` を使用して可読性を上げる
- `managed-settings.d/` のチーム共有ポリシーファイルで新エイリアスに統一する

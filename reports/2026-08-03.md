# Claude Code ベストプラクティス調査レポート 2026-08-03

## 今週の新発見

### ワークフロー設定: `workflowSizeGuideline` でエージェント数を制御（v2.1.219）

**発見内容**: `workflowSizeGuideline` 設定が追加され、動的ワークフロー（Workflow ツール）が生成するサブエージェント数の推奨上限を任意の設定ファイルから指定できるようになった。ワークフローのステータス行にも現在のデフォルトサイズが常時表示される。

```json
// .claude/settings.json
{
  "workflowSizeGuideline": "medium"
}
// 値: "small"（目安 <5 エージェント）/ "medium"（目安 <15）/ "large"（制限なし）
```

環境変数でも上書き可能:
```bash
CLAUDE_CODE_WORKFLOW_SIZE_GUIDELINE=small claude
```

設計パターン別の推奨サイズ:
| ユースケース | 推奨サイズ |
|------------|-----------|
| CI/Routines（コスト最優先） | small |
| 通常の開発ワークフロー | medium（デフォルト） |
| 大規模監査・移行タスク | large |

**適用提案**:
- `~/.claude/settings.json` に `"workflowSizeGuideline": "medium"` を設定してデフォルトを明示化する
- CI/Routines 環境では `CLAUDE_CODE_WORKFLOW_SIZE_GUIDELINE=small` を環境変数で固定し過剰課金を防ぐ
- チーム共有の `.claude/settings.json` では `"medium"` を基準とし、特定タスクで CLI から `"large"` に上書きする

### Hooks: `Notification` フックでバックグラウンドエージェントをモニタリング

**発見内容**: `Notification` フックイベントが確認された。バックグラウンドエージェントの状態変化（入力待ち・完了）を受け取り、Slack/デスクトップ通知・ログ等に転送できる。

フックペイロードの `notification_type` フィールド:
- `"agent_needs_input"`: バックグラウンドエージェントが人間の入力を待っている
- `"agent_completed"`: バックグラウンドエージェントが完了した

```json
// .claude/settings.json
{
  "hooks": {
    "Notification": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "notify-send 'Claude Code' \"$CLAUDE_NOTIFICATION_TYPE: $CLAUDE_NOTIFICATION_MESSAGE\""
          }
        ]
      }
    ]
  }
}
```

Slack 転送の例:
```bash
#!/bin/bash
# ~/.claude/hooks/notify-slack.sh
TYPE="$CLAUDE_NOTIFICATION_TYPE"
MSG="$CLAUDE_NOTIFICATION_MESSAGE"
SESS="$CLAUDE_SESSION_ID"

if [ "$TYPE" = "agent_needs_input" ]; then
  curl -s -X POST "$SLACK_WEBHOOK_URL" \
    -H 'Content-type: application/json' \
    --data "{\"text\": \":pause_button: Claude エージェントが入力待ちです（session: $SESS）: $MSG\"}"
fi
```

**適用提案**:
- `Notification` フックで `~/.claude/hooks/notify.sh` を作成し、バックグラウンドエージェントの `agent_needs_input` を即座に通知する
- `agent_completed` 受信時に自動で次のステップを起動するパイプラインを hooks で実装できる
- 長時間 Routine タスクでの見落とし防止に特に有効

### Context Engineering: Claude API の 3 プリミティブ（エージェント開発向け）

**発見内容**: Claude API（Messages API）の公式クックブックで、長時間エージェントのコンテキスト管理に使う 3 プリミティブが整理された。Claude Code 内のサブエージェント開発・MCP ツール実装時にも適用可能。

| プリミティブ | 効果 | コスト | ユースケース |
|------------|------|--------|------------|
| Compaction (`compact_20260112`) | 対話履歴をサマリで置換 | 推論コストあり | 長い会話・推論ループ |
| Tool-Result Clearing (`clear_tool_uses_20250919`) | 古いツール結果を消去 | ゼロ（機械的） | ファイル読み込み多数・API レスポンス蓄積 |
| Memory Tool (`memory_20250818`) | セッション間で情報を永続化 | ゼロ（取得時） | マルチセッションワークフロー |

**Compaction 設定例**（Messages API 呼び出し時）:
```python
context_management={
    "edits": [{
        "type": "compact_20260112",
        "trigger": {"type": "input_tokens", "value": 150_000},
        "instructions": "変更ファイルリストとテストコマンドを保持。実装の理由を保持。"
    }]
}
```

**Tool-Result Clearing 設定例**（ファイル読み込みループで有効）:
```python
context_management={
    "edits": [{
        "type": "clear_tool_uses_20250919",
        "trigger": {"type": "input_tokens", "value": 30_000},
        "keep": {"type": "tool_uses", "value": 4},   # 直近4回分を保持
        "clear_at_least": {"type": "input_tokens", "value": 10_000}
    }]
}
# 効果: ファイル読み込みワークロードで最大67%のトークン削減
```

**問題→解法マッピング**:
```
対話・推論の蓄積       → Compaction
再取得可能なツール結果  → Clearing
セッション間の知識保持  → Memory Tool
```

**適用提案**:
- カスタムサブエージェント・MCP ツールを Messages API で構築する際は 3 プリミティブを組み合わせてピークコンテキストを 50% 削減する
- Claude Code 内で `/compact` を手動実行する際、カンパクション指示に「変更ファイルリストとテストコマンドを保持」と記載すると Compaction API の `instructions` 相当の効果が得られる
- ファイル読み込みを大量に行う Explore/Grep 多用セッションでは早めに `/compact` を実行し Tool-Result の蓄積をリセットする

### MCP 運用: デバッグパターンとスターターセット最新版

**発見内容**: MCP サーバーが増えるほどコンテキスト消費とツール選択精度が悪化する。50 ツール超で誤選択が顕著に増加。デバッグの最速手順も明確化されている。

**MCP デバッグ手順（推奨順）**:
1. `jq . .claude/settings.json` で JSON 構文エラーを先に排除
2. MCP サーバーの起動コマンドをターミナルで直接実行して生のエラーを確認
3. `claude mcp list` / `/mcp` で接続状態と HTTP ステータスを確認（v2.1.219 でエラーテキスト表示強化）
4. `.claude/settings.json` の環境変数値に前後の空白が入っていないか確認（v2.1.219 で警告追加）

**2026 年の推奨スターターセット（最小実用構成）**:
```json
// .claude/settings.json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/home/user/projects"]
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_TOKEN}" }
    },
    "context7": {
      "command": "npx",
      "args": ["-y", "@upstash/context7-mcp"]
    }
  }
}
```

セキュリティ原則:
- 本番 DB は **read-only ロール**で接続（write アクセスは明示的に必要な場合のみ）
- API トークンは `.mcp.json` にハードコードせず `${ENV_VAR}` 展開で注入
- 追加するサーバーは「実際のユースケースが既にある」場合のみ（AI 検索系は特にコンテキスト汚染リスクが高い）

**適用提案**:
- `~/.claude/settings.json` のグローバル MCP は filesystem + github + context7 の 3 本に絞る
- プロジェクト固有のサーバー（playwright, postgres 等）はプロジェクトの `.claude/settings.json` に分離する
- v2.1.219 の MCP エラー表示強化を活用し、`claude mcp list` を日常的なヘルスチェックに組み込む

### スキル vs スラッシュコマンドの役割整理（運用指針）

**発見内容**: Claude Code 公式ドキュメントおよびコミュニティで、スキルとスラッシュコマンドの使い分けが整理された。この区別は CLAUDE.md のどこに何を書くかの判断基準にも直結する。

**4象限の判断フレームワーク**:

| 何をしたいか | 使うもの |
|------------|---------|
| ルールを強制（許可/拒否） | **Hooks / permissions** |
| コンテキスト知識を注入 | **Skills**（オンデマンドロード） |
| 委譲境界を定義 | **Subagents**（`.claude/agents/`） |
| 常時有効なプロジェクトガイダンス | **CLAUDE.md**（短く保つ） |

**スキル vs スラッシュコマンドの決定木**:
```
明示的に呼び出したい（手動実行）
  → スラッシュコマンド（.claude/commands/ または .claude/skills/ + user-invocable: true）

Claude が自動的にコンテキストを判断してロードしてほしい
  → スキル（.claude/skills/<name>/SKILL.md）

常に全セッションで必要
  → CLAUDE.md に記載

2回以上同じコードを貼り付けた
  → Skill 化を検討

毎回コピー&ペーストしている操作
  → MCP ツール化を検討
```

**適用提案**:
- 既存の CLAUDE.md を見直し、「Claude に自動判断させたいコンテキスト」は `.claude/skills/` へ、「常時必要なガイダンス」だけ CLAUDE.md に残す
- 手動でよく実行するワークフロー（リリース手順・DBマイグレーション等）はスラッシュコマンドとして `.claude/commands/` に格納する
- `user-invocable: true` フロントマターを付けたスキルは `/skill-name` で明示的に呼び出せるため、スラッシュコマンドとスキルを統合管理できる

### `vimInsertModeRemaps` 設定（v2.1.219）

**発見内容**: Vim モードのインサートモードキーバインドを `settings.json` でカスタマイズできる `vimInsertModeRemaps` が追加された。`jj` で `<Esc>` に戻る等のカスタマイズが設定ファイルで管理できる。

```json
// ~/.claude/settings.json
{
  "vimInsertModeRemaps": {
    "jj": "<Esc>",
    "jk": "<Esc>"
  }
}
```

同時に Vim モードの空プロンプトで `←` キーが正しく機能しないバグも修正された（v2.1.219）。

**適用提案**:
- Vim ユーザーは `~/.claude/settings.json` に `vimInsertModeRemaps` を追加して使い慣れたキーバインドを設定する
- チーム設定（`.claude/settings.json`）には入れず、個人設定（`~/.claude/settings.json`）に留める

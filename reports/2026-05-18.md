## 今週の新発見

### Hooks リファレンス完全版 ― 28+イベント・5ハンドラータイプの全容

**発見内容**: 公式リファレンス（v2.1.141+）でフックイベントが **28以上** に拡張され、ハンドラータイプも5種類が揃った。過去レポートで扱いきれていなかった詳細を整理する。

#### 今週新たに確認したイベント

| イベント | カデンス | 用途 |
|---------|---------|------|
| `PostToolBatch` | Per-tool | 並列バッチ完了後。exit 2 で次のモデル呼び出し前にループを停止 |
| `PermissionDenied` | Per-tool | auto モードが拒否した後。`retry: true` で Claude に再試行を促す |
| `SubagentStart/Stop` | Per-tool | サブエージェントのライフサイクル管理 |
| `TaskCreated/TaskCompleted` | Task | タスク管理。exit 2 でブロック可能 |
| `TeammateIdle` | Per-tool | エージェントチームでの待機状態 |
| `Elicitation/ElicitationResult` | UI | MCP サーバーがユーザー入力を要求/回答時 |
| `StopFailure` | Per-turn | API エラーで会話ターン終了時 |
| `UserPromptExpansion` | Per-turn | スラッシュコマンド展開時。exit 2 でブロック可能 |

#### `asyncRewake` ― バックグラウンドから Claude を起こす

```json
{
  "type": "command",
  "command": ".claude/hooks/check-ci.sh",
  "asyncRewake": true
}
```

`async: true` と異なり、**exit 2 を返すと Claude が再び起動**される。長時間の CI 監視・外部システムのポーリングに最適。`asyncRewake` を設定すると `async: true` は自動的に適用される。

#### `terminalSequence` ― ターミナル通知の送信

```bash
#!/bin/bash
input=$(cat)
body=$(jq -r '.message // "Needs attention"' <<<"$input")
seq=$(printf '\033]777;notify;Claude Code;%s\007' "$body")
jq -nc --arg seq "$seq" '{terminalSequence: $seq}'
```

フックから直接ターミナル通知（OSC 777 = Ghostty/Warp 対応）を送信できる（v2.1.141+）。

#### `additionalContext` ― Claude のコンテキストに動的情報を注入

```bash
#!/bin/bash
jq -nc '{
  hookSpecificOutput: {
    hookEventName: "SessionStart",
    additionalContext: "Current branch: main\nOpen issues: #142, #156\nLast deploy: 2 hours ago"
  }
}'
```

**10,000文字上限**。超えた場合はファイルに保存されリンクが渡される。**注意**: 指示形式（「You must...」「Never allow...」）はプロンプトインジェクション防御に引っかかる。事実ベースの文章（「The deployment target is production」）で記述すること。

#### `modifiedInput` ― PreToolUse でツール入力を書き換える

```json
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "allow",
    "modifiedInput": {
      "command": "npm run lint -- --fix"
    }
  }
}
```

Claude が提案したコマンドを安全な代替に差し替えて許可できる。

#### `mcp_tool` ハンドラー ― MCP サーバーをフックから呼ぶ

```json
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Write|Edit",
      "hooks": [{
        "type": "mcp_tool",
        "server": "security_scanner",
        "tool": "scan_file",
        "input": { "file_path": "${tool_input.file_path}" },
        "timeout": 60
      }]
    }]
  }
}
```

`${tool_input.file_path}` のようなパスで、フックの JSON 入力から値を参照できる。

#### HTTP フックの `allowedEnvVars`

```json
{
  "type": "http",
  "url": "http://localhost:8080/validate",
  "headers": { "Authorization": "Bearer $API_TOKEN" },
  "allowedEnvVars": ["API_TOKEN"]
}
```

HTTP フックのヘッダーで環境変数を展開する際は `allowedEnvVars` で明示的に許可リストに載せる必要がある。

**適用提案**:
- `~/.claude/settings.json` の `hooks` ブロックに `PostToolUse` (Write|Edit) → lint/format スクリプトを追加
- CI 連携は `asyncRewake: true` フックで実装し、失敗時のみ Claude を起動
- `SessionStart` フックで `additionalContext` に現在ブランチ・オープン Issue を注入してセッション毎の手動コピペを廃止
- `PreToolUse` の `modifiedInput` でデストラクティブなコマンドを安全版に自動変換

### サブエージェント管理の進化 ― `/agents` UI・CLIフラグ・スコープ優先度

**発見内容**: サブエージェント定義とライフサイクル管理が大幅に整備された。

#### `/agents` コマンドによる UI 管理

`/agents` を実行すると2タブ構成のインターフェースが開く:

| タブ | 内容 |
|------|------|
| **Running** | 実行中のサブエージェント一覧・停止 |
| **Library** | 利用可能な全サブエージェント・作成・編集・削除 |

Library タブの「Generate with Claude」でサブエージェントの内容を自然言語で説明すると、Claude がフロントマターとシステムプロンプトを自動生成する。

#### スコープ優先度（高→低）

| スコープ | 配置場所 | 優先度 |
|---------|---------|--------|
| Managed | 組織ポリシー | 1（最高） |
| CLI フラグ | `--agents` フラグ | 2 |
| プロジェクト | `.claude/agents/` | 3 |
| ユーザー | `~/.claude/agents/` | 4 |
| プラグイン | プラグインの `agents/` | 5 |

同名のエージェントが複数スコープに存在する場合、優先度が高い方が有効になる。

#### CLI-defined サブエージェント ― 一時的な定義

```bash
claude --agents '{
  "code-reviewer": {
    "description": "Expert code reviewer. Use proactively after code changes.",
    "prompt": "You are a senior code reviewer. Focus on code quality, security, and best practices.",
    "tools": ["Read", "Grep", "Glob", "Bash"],
    "model": "sonnet"
  }
}'
```

セッション限定で有効。スクリプト・自動化パイプラインでの一時エージェント定義に便利。

#### サブエージェントの永続メモリ

```markdown
---
name: code-improver
description: コード品質向上の提案を行う
memory: user
---
```

`memory: user` を指定すると `~/.claude/agent-memory/<name>/` に知識が蓄積され、セッション間をまたいでコードパターン・課題傾向を記憶する。

#### Explore エージェントの thoroughness

`Explore` エージェント（組み込み）を使う際は thoroughness レベルを指定できる:
- `quick`: 単一ターゲットの絞り込み検索
- `medium`: バランスの取れた探索
- `very thorough`: 複数箇所・命名規則を横断した徹底検索

**適用提案**:
- `~/.claude/agents/` にユーザーレベルの汎用エージェント（security-reviewer、test-writer など）を配置してすべてのプロジェクトで再利用
- プロジェクト固有のエージェントは `.claude/agents/` に配置して git 管理（チーム共有）
- `memory: user` 付きの「tech-debt-tracker」エージェントで技術的負債を継続的に追跡

### settings.json 新設定項目 ― v2.1.90〜v2.1.117

**発見内容**: この数ヶ月で追加された設定項目のうち、過去レポートで未紹介のもの。

#### `advisorModel` ― セカンダリアドバイザーモデル（v2.1.90+）

```json
{
  "advisorModel": "claude-opus-4-7"
}
```

メインモデルとは別に、特定の判断に使うアドバイザーモデルを設定できる。Plan Mode の推論フェーズに Opus を充てながら、実装は Sonnet で行うような構成が自動化される。

#### `alwaysThinkingEnabled` ― 拡張思考の常時有効化

```json
{
  "alwaysThinkingEnabled": true,
  "showThinkingSummaries": true
}
```

`alwaysThinkingEnabled: true` で全セッションで Extended Thinking が常にオン。`showThinkingSummaries: true` で思考サマリーを表示（思考の全文ではなく要約）。

#### `cleanupPeriodDays: 0` ― セッション履歴の無効化

```json
{
  "cleanupPeriodDays": 0
}
```

`0` に設定するとセッション履歴がディスクに書き込まれなくなる。プライバシー要件が厳しい環境（医療・金融）での運用に有用。

#### `disableAllHooks: true` ― 全フックの一括無効化

```json
{
  "disableAllHooks": true
}
```

`.claude/settings.json` に記述すると、そのプロジェクトの全フックを無効化。デバッグ時やフック起因の問題切り分けに使う。

#### Deny-first の権限評価順序

```json
{
  "permissions": {
    "deny": ["Bash(rm -rf *)"],
    "ask": ["Bash(git push *)"],
    "allow": ["Bash(npm run *)"]
  }
}
```

評価順序: **deny → ask → allow**（最初にマッチしたルールが適用）。過去に `allow` と `deny` の2ティアしか認識していなかったが、`ask`（確認プロンプト）を間に挟む3ティア構成が公式仕様として確認された（2026-04-27レポートを補強）。

**適用提案**:
- `~/.claude/settings.json` に `advisorModel: "claude-opus-4-7"` を設定して Plan Mode の思考品質を向上
- CI/CD 用プロジェクトでは `cleanupPeriodDays: 0` でセッション履歴の残留を防ぐ
- フックデバッグ中は `disableAllHooks: true` をローカル設定に追加して問題の切り分けを高速化

### CLAUDE.md とスキルの明確な住み分けルール

**発見内容**: 公式ドキュメントが CLAUDE.md とスキルの役割分担を明文化した。

#### 原則

| ファイル | ロードタイミング | 用途 |
|---------|--------------|------|
| **CLAUDE.md** | 毎セッション自動ロード | すべてのタスクに常に適用する普遍的なルール |
| **Skills (`SKILL.md`)** | 必要に応じてオンデマンドロード | 特定のワークフローや知識（API 規約など） |

**CLAUDE.md が長くなりすぎたら**: 特定の作業にしか関係しない内容はスキルに移す。スキルはコンテキストを汚さない。

#### 「CLAUDE.md をコードとして扱え」原則

> "Treat CLAUDE.md like code: review it when things go wrong, prune it regularly, and test changes by observing whether Claude's behavior actually shifts."

- 動作がおかしい時にレビューする
- 定期的に刈り込む
- 変更したら Claude の挙動が実際に変わるか確認する

#### スキルによる API 規約の切り出し例

```markdown
<!-- .claude/skills/api-conventions/SKILL.md -->
---
name: api-conventions
description: REST API design conventions for our services
---
# API Conventions
- Use kebab-case for URL paths
- Use camelCase for JSON properties
- Always include pagination for list endpoints
- Version APIs in the URL path (/v1/, /v2/)
```

このような内容を CLAUDE.md に書くと全セッションで読み込まれるが、スキルにすることでリクエスト時のみロードされる。

**適用提案**:
- CLAUDE.md から「APIエンドポイント命名規則」「DB スキーマ詳細」「特定フレームワークの慣習」などをスキルに分離
- CLAUDE.md に残すのは「テストランナーのコマンド」「ブランチ命名規則」「必須環境変数」など普遍的なもののみ

### コンテキスト管理の詳細 ― `/rewind` の5オプションと「2回修正ルール」の公式化

**発見内容**: `/rewind` と `/compact` の詳細なオプションが公式化された。

#### `/rewind` の5つの操作

`Esc+Esc` または `/rewind` を実行すると、チェックポイント選択メニューが開く:

| オプション | 効果 |
|-----------|------|
| **Restore conversation** | 会話のみ元に戻す（コードはそのまま） |
| **Restore code** | コードのみ元に戻す（会話はそのまま） |
| **Restore both** | 会話・コードを両方元に戻す |
| **Summarize from here** | 選択地点以降を圧縮（以前のコンテキストは保持） |
| **Summarize up to here** | 選択地点以前を圧縮（以降の最新コンテキストは保持） |

「Summarize from here」と「Summarize up to here」を組み合わせることで、**重要な過去コンテキストを保持しながら特定区間だけを圧縮**するという精密な操作が可能になった。

#### 「2回修正ルール」の公式化

> "If you've corrected Claude more than twice on the same issue in one session, the context is cluttered with failed approaches. Run `/clear` and start fresh with a more specific prompt."

公式ドキュメントが明記: **同じ問題で2回修正しても直らない場合は即座に `/clear`**。長いセッションへの補正を続けるより、良いプロンプトでクリーンスタートの方が高品質な出力を得られる。

**適用提案**:
- 「2回修正ルール」をチームに共有し、修正ループに陥った場合の標準対応とする
- `/compact Focus on the authentication changes` で作業関連コンテキストのみ保持しながら圧縮
- Ctrl+G でプランをテキストエディタ編集してから実装（Plan Mode の活用を最大化）

### CLI Fan-out パターンの詳細 ― `--allowedTools` 構文と `--permission-mode auto`

**発見内容**: 大規模並列化（Fan-out）のベストプラクティスが整理された。

#### `--allowedTools` の詳細構文

```bash
# 単一ファイルマイグレーションをバッチ実行
for file in $(cat files.txt); do
  claude -p "Migrate $file from React to Vue. Return OK or FAIL." \
    --allowedTools "Edit,Bash(git commit *)"
done
```

`Bash(git commit *)` のように `ToolName(pattern)` 形式でコマンドを限定できる。バッチ実行時の権限最小化に必須。

#### `--permission-mode auto` ― 無人実行の安全弁

```bash
claude --permission-mode auto -p "fix all lint errors"
```

auto モードでは Classifier がコマンドを審査し、スコープ逸脱・未知インフラ・敵対的コンテンツ駆動の操作をブロック。`-p` フラグとの組み合わせで、Classifier が繰り返しブロックする場合は自動的に中断（ユーザーにフォールバックできないため）。

#### ストリーミング出力のパイプライン統合

```bash
# 構造化出力でパイプライン統合
claude -p "List all API endpoints" --output-format json | jq '.endpoints[]'

# ストリーミング JSON でリアルタイム処理
claude -p "Analyze this log file" --output-format stream-json | process_stream.py
```

**適用提案**:
- 大規模マイグレーション（1000ファイル超）では `xargs -P 5` + `claude -p` で並列 Fan-out
- バッチ実行時は `--allowedTools "Edit,Bash(git add *),Bash(git commit *)"` で権限を最小化
- CI パイプラインには `--permission-mode auto --output-format json` を標準オプションとして設定

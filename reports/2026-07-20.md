# Claude Code ベストプラクティス調査レポート 2026-07-20

## 今週の新発見

### `/fork` と `/subtask` の役割再分割（v2.1.212）

**発見内容**: これまで `/fork` がサブエージェントの起動を担っていたが、v2.1.212 でコマンドの役割が明確に分離された。

| コマンド | 旧動作 | 新動作 |
|---------|--------|--------|
| `/fork` | サブエージェントを起動（廃止） | 現在の会話をバックグラウンドセッションとしてコピー |
| `/subtask` | 存在しなかった | セッション内サブエージェントを即時起動（新設） |

```text
# セッションを分岐してバックグラウンドで別方向を試す
> /fork "この実装方針は一旦保留して、別アプローチを試す"

# 現セッション内でサブエージェントに特定タスクを委譲する
> /subtask セキュリティ観点でこのコードをレビューして
```

`/resume` も同様に更新され、過去セッションをバックグラウンドセッションとして再開するインタラクティブピッカーに進化した。

**適用提案**:
- 「方針を変えて試したいが今の作業は捨てたくない」→ `/fork` でスナップショット保存してから新方針へ
- 「調査だけ別エージェントに任せたい」→ `/subtask` でセッション内サブエージェントを起動
- `.claude/agents/` 定義を使う場合は引き続き Agent ツール経由で起動可能

### セッション単位の上限設定（v2.1.212）

**発見内容**: 暴走ループ・コスト超過を防ぐセッション単位の上限が追加された。デフォルトはいずれも 200。

| 環境変数 | 対象 | デフォルト | リセット |
|---------|------|-----------|---------|
| `CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION` | WebSearch 呼び出し数 | 200 | `/clear` |
| `CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION` | サブエージェント起動数 | 200 | `/clear` |

```bash
# コスト上限を厳格にしたい場合（.claude/settings.json や CI 環境変数に設定）
export CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION=20
export CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION=10
```

また MCP ツールが 2 分（デフォルト）以上かかる場合、自動でバックグラウンドに移行するようになった。

```bash
# MCP バックグラウンド移行のしきい値を変更（ミリ秒）
export CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS=60000  # 1分に短縮
```

**適用提案**:
- CI・Routines 環境では WebSearch 上限を 10〜20 に絞り、意図しない費用増を防ぐ
- 応答が遅い MCP サーバーは `CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS` を小さくしてメインループのブロックを回避する
- 上限に達した場合は `/clear` でリセットできるため、長時間タスクは中間チェックポイントで `/clear` を挟む設計にする

### Auto-mode スキルの手動実行化（v2.1.215）

**発見内容**: v2.1.215 から `/verify` と `/code-review` スキルが **デフォルトで自動実行されなくなった**。Claude が作業完了後に自動起動していた動作が廃止され、ユーザーが明示的に呼び出す必要がある。

```text
# 以前: Claude が実装完了後に自動で /verify を実行していた
# 今後: 明示的に呼び出す

> /verify     # 実装後に手動で呼び出す
> /code-review --fix  # コードレビューと修正を手動でトリガー
```

背景: Auto-mode で不要なタスクにも `/verify` が走りコンテキストを消費していた問題への対処。

**適用提案**:
- 既存のワークフローで `/verify` 自動実行を前提にしている場合は `Stop` フックで代替できる:

```json
{
  "hooks": {
    "Stop": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "if": "Stop(subtype=task_complete)",
            "command": "echo '⚠️ 実装完了。/verify を実行してください'"
          }
        ]
      }
    ]
  }
}
```

- CLAUDE.md または `Stop` フックで「実装後は `/verify` を実行すること」と明示するか、チームの Skill にチェックリストとして組み込む

### hooks の `if` フィールドによる事前フィルタリング（パフォーマンス最適化）

**発見内容**: フック設定の `if` フィールドはプロセスを起動する**前**に評価される。これにより、不要なプロセス起動コストを完全に排除できる。

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "if": "Bash(npm *)",
            "command": "./hooks/validate-npm.sh"
          }
        ]
      }
    ]
  }
}
```

`matcher: "Bash"` で全 Bash コマンドにマッチさせつつ、`if: "Bash(npm *)"` でプロセス起動前に npm 関連のみに絞り込める。

また、`updatedInput`（PreToolUse）と `updatedToolOutput`（PostToolUse）を使ってツールの入出力を書き換える応用パターンも公式ドキュメントに追加された:

```bash
# PreToolUse でコマンドを書き換えてから実行
jq -n --arg cmd "$sanitized_cmd" '{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "allow",
    "updatedInput": { "command": $cmd }
  }
}'
```

**適用提案**:
- 既存フックで `matcher` を細かく設定している場合でも、`if` フィールドを追加してプロセス起動コストをさらに削減する
- フック全体の処理時間を測定し、100ms を超えているものは `async: true` への移行か `if` フィールドによるフィルタ強化を検討する
- `updatedInput` で機密ファイルパスのサニタイズや引数の正規化を行うことで、Claude への明示的な指示を減らせる

### OpenTelemetry 強化 & 新ツール（v2.1.214）

**発見内容**: Claude Code の可観測性が強化され、エンタープライズ用途に使えるメトリクスが追加された。

#### OpenTelemetry の新属性
```bash
# OpenTelemetry コンテンツの切り詰めサイズを調整（デフォルト 60 KB）
export CLAUDE_CODE_OTEL_CONTENT_MAX_LENGTH=30000  # 30 KB に短縮してログコスト削減
```

新しいスパン属性:
- `message.uuid`: メッセージレベルの相関 ID
- `client_request_id`: クライアントリクエスト識別子
- `tool_source`: ツールの呼び出し元（built-in / mcp / plugin）

#### `EndConversation` ツール
Claude が不正利用・ジェイルブレイク試行を検知した場合にセッションを自律的に終了できる `EndConversation` ツールが追加された。チームの利用規約・セキュリティポリシーを CLAUDE.md に明記することで、より確実に動作する。

#### メモリファイルへのタイムスタンプ追加
`~/.claude/projects/<project>/memory/*.md` のフロントマターに ISO 8601 形式の `modified` タイムスタンプが自動付与されるようになった。

```yaml
---
modified: 2026-07-18T09:32:11Z
---
# My Project Context
...
```

**適用提案**:
- OpenTelemetry を利用しているチームは `CLAUDE_CODE_OTEL_CONTENT_MAX_LENGTH` を設定してログストレージコストを最適化する
- `tool_source` 属性を活用して「MCP 経由 vs ビルトインツール」の使用率を分析し、MCP サーバーの費用対効果を評価する
- メモリファイルのタイムスタンプを見て古い記憶（30日以上前）を定期的に整理するフローを構築する

### パーミッションルールの構文警告（v2.1.210）

**発見内容**: 非推奨のパーミッション記述形式を使っていると起動時に警告が表示されるようになった。

```text
# 起動時の警告例（v2.1.210+）
⚠ Deprecated permission syntax: Write() → use Edit() instead
⚠ Deprecated permission syntax: Glob() → use Read() with glob patterns
```

具体的に非推奨になった記述:
- `Write()` → `Edit()` を使う
- `NotebookEdit()` → `Edit()` に統合
- `Glob()` → `Read()` のグロブパターン指定を使う

また `dir/**` の allow ルールが `<cwd>/dir` 配下のみを正確に対象とするよう修正された（バグ修正）。

**適用提案**:
- `~/.claude/settings.json` および `.claude/settings.json` の `permissions.allow/deny` を確認し、`Write()`・`Glob()` を新形式に更新する
- CI で起動時ログを確認し、deprecation 警告がゼロになるまでクリーンアップする

## 今週の適用アクションリスト

- [ ] **`/fork` と `/subtask` の使い分けを習慣化**: 方針分岐には `/fork`、即時サブタスクには `/subtask` を使う
- [ ] **セッション上限を設定**: CI/Routines の `settings.json` に `CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION=20` と `CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION=20` を設定する
- [ ] **`/verify` 自動実行の代替フローを用意**: `Stop` フックで完了通知を出すか、CLAUDE.md に「実装後は `/verify` を実行」と明記する
- [ ] **フックの `if` フィールドを追加**: 既存の高頻度フック（Bash 全体にマッチしているもの）に `if` フィールドを付加してプロセス起動コストを削減する
- [ ] **パーミッション構文の更新**: `Write()` → `Edit()`、`Glob()` → `Read()` に更新して起動時 deprecation 警告をゼロにする
- [ ] **MCP auto-background しきい値を調整**: 遅い MCP サーバーには `CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS` を設定する
- [ ] **OpenTelemetry 利用者は `CLAUDE_CODE_OTEL_CONTENT_MAX_LENGTH` を最適化**: ログコスト削減のために 30–60 KB 範囲で調整する

# Claude Code ベストプラクティス調査レポート 2026-06-22

## 今週の新発見

### managed-settings.d/ ドロップインディレクトリ ― チームポリシーの断片化管理

**発見内容**: managed-settings.json の隣に `managed-settings.d/` ディレクトリを置くことで、複数チーム・ツールが独立した JSON ファイルでポリシーを管理できる。systemd の drop-in 方式と同じ考え方で、ファイルはアルファベット順にマージされる（スカラーは後優先・配列は連結+重複排除・オブジェクトはディープマージ）。

```
/etc/claude-code/managed-settings.json        ← ベース
/etc/claude-code/managed-settings.d/
  10-telemetry.json                           ← 監視チームポリシー
  20-security.json                            ← セキュリティチームポリシー
  30-devtools.json                            ← 開発ツールチームポリシー
```

ファイル命名は数字プレフィックスで優先度制御。`.` 始まりは無視される。

**適用提案**:
- セキュリティ、コンプライアンス、開発ツールチームがそれぞれ独立ファイルでポリシーを管理し、単一ファイルへの競合編集を排除する
- `10-base.json`（全員共通）→ `50-team-specific.json`（チーム固有）→ `90-emergency.json`（緊急ブロック）のような階層を設計する

### 新 settings.json 項目 ― footerLinksRegexes / axScreenReader / policyHelper

**発見内容**: 2026年5月〜6月に新しい設定項目が複数追加された。

#### `footerLinksRegexes`（v2.1.176+）
入力欄フッターに正規表現マッチでクリッカブルバッジを表示。`PROJ-1234` などのチケット ID を自動リンク化できる。

```json
"footerLinksRegexes": [
  {
    "type": "regex",
    "pattern": "\\b(?<key>PROJ-\\d+)\\b",
    "url": "https://issues.example.com/browse/{key}",
    "label": "{key}"
  },
  {
    "type": "regex",
    "pattern": "\\b(?<key>GH-\\d+)\\b",
    "url": "https://github.com/org/repo/issues/{key}",
    "label": "#{key}"
  }
]
```

#### `axScreenReader`（v2.1.181+）
スクリーンリーダー向けにフラットテキストで出力（装飾ボーダー・アニメーションなし）。

```json
"axScreenReader": true
```

#### `disableClaudeAiConnectors`（v2.1.182+）
claude.ai MCP コネクタの自動フェッチを無効化。エンタープライズ環境で組織外コネクタを遮断したいときに使用。

```json
"disableClaudeAiConnectors": true
```

#### `policyHelper`（v2.1.136+）
起動時に実行されるアドミン向け実行ファイル。デバイスポスチャ・ID・リモートサービスからポリシーを動的計算できる（managed-settings.json のみ有効）。

```json
"policyHelper": {"path": "/usr/local/bin/claude-policy"}
```

#### 単一設定の即時更新
```bash
# インターフェイス不要でワンライナー設定変更
/config verbose=true
/config defaultMode=acceptEdits
```

**適用提案**:
- Jira / Linear / GitHub Issues を使うプロジェクトでは `footerLinksRegexes` を設定し、チケット番号をワンクリックで開けるようにする
- エンタープライズ環境の CI/CD では `disableClaudeAiConnectors: true` + `policyHelper` で外部コネクタを制御する

### Hooks ― 37イベント全容・非同期フック・出力変換

**発見内容**: 最新ドキュメントで hooks イベント数が **37** に確定した。既存の記録から追加された新規イベントと新機能：

#### 新規イベント（前回未確認）
| イベント | タイミング |
|---------|----------|
| `Elicitation` | MCP サーバーが確認を要求するとき |
| `ElicitationResult` | ユーザーが確認に応答したとき |
| `MessageDisplay` | メッセージが表示される直前 |
| `TeammateIdle` | エージェントチームのメンバーがアイドルになったとき |
| `TaskCreated` | タスクが作成されたとき |
| `TaskCompleted` | タスクが完了したとき |

#### `async: true` ― ノンブロッキングバックグラウンドフック
```json
{
  "hooks": {
    "PostToolUse": [{
      "type": "command",
      "command": "/path/to/slow-audit.sh",
      "async": true
    }]
  }
}
```
メインフローをブロックせずバックグラウンドで実行。セキュリティ監査・通知送信などに使用。

#### `asyncRewake: true` ― バックグラウンド完了時の Claude 再起動
```json
{
  "hooks": {
    "Stop": [{
      "type": "command",
      "command": "/path/to/long-test.sh",
      "asyncRewake": true
    }]
  }
}
```
長時間テストがバックグラウンドで完了したとき、exit code 2 + stderr で Claude を再起動できる。

#### `terminalSequence` ― デスクトップ通知（v2.1.141+）
```json
{
  "terminalSequence": "\033]777;notify;Claude Code;ビルド完了\007"
}
```
`/dev/tty` 不要でデスクトップ通知を送信できる。Stop フックと組み合わせてタスク完了を通知するのが最適。

#### `updatedToolOutput` ― ツール出力の変換・リダクション
PostToolUse フックから機密情報をマスクしてから Claude のコンテキストに渡せる：
```json
{
  "hookSpecificOutput": {
    "hookEventName": "PostToolUse",
    "updatedToolOutput": "[REDACTED: contains secret keys]"
  }
}
```

#### Stop フックの 8 回ブロック上限
Stop フックが連続 8 回ブロックすると Claude が強制的にターンを終了する。無限ループ防止のための組み込みセーフガード。`stop_hook_active` 環境変数でフック内から自身を検出できる。

**適用提案**:
- 長時間テスト（E2E・統合テスト）は `asyncRewake: true` で Stop フックに設定し、テスト完了後に Claude が結果を受け取れるようにする
- `terminalSequence` 通知を Stop フックに追加し、エージェントタスクが完了したときの PC 通知を自動化する
- 機密情報（APIキー・PII）が含まれる可能性のあるコマンド出力は `updatedToolOutput` でリダクションを実装する

### MCP ― ツール数上限と Streamable HTTP 移行

**発見内容**: MCP サーバーの実用的な制約とトランスポート移行について公式情報が明確化された。

#### ツール数のソフト上限
- **40 ツール**: 安定動作の目安
- **50 ツール超**: モデルが誤ったツールを選択し始める
- Tool Search（Sonnet 4 以上）でオンデマンド取得すればこの制約を緩和できる

#### Streamable HTTP が新標準
2025年11月の MCP 仕様改定で旧 HTTP+SSE が **Streamable HTTP** に置き換えられた。推奨トランスポート選択：

```
ローカルマシン上のサーバー → stdio
リモート/クラウドサーバー   → Streamable HTTP (OAuth 2.1)
ベンダーがまだ未対応        → SSE（暫定のみ）
```

#### スコープ設計の原則
```
~/.claude/settings.json   → 全プロジェクトで使う安定ツール（GitHub, Slack 等）
.claude/settings.json     → プロジェクト固有 API・DB（リポジトリごとに必要なもののみ）
.mcp.json                 → チーム共有設定（git 管理）
```

**適用提案**:
- MCP サーバー追加時に現在の有効ツール数を確認し、40 を超えたら不使用サーバーを整理する
- ローカルで stdio を使っているサーバーはそのままで良いが、社内共有サーバーを立てる場合は Streamable HTTP + OAuth 2.1 で設計する
- `.mcp.json` をリポジトリにコミットしてチーム全員が同一 MCP 環境を使えるようにする

### CLAUDE.md ― コンパクション指示の埋め込みと @インポート

**発見内容**: 公式ドキュメントで CLAUDE.md にコンパクション指示を埋め込む手法が明文化された。`/compact` 実行時（自動・手動問わず）にどの情報を保持するかを Claude に指示できる。

```markdown
<!-- CLAUDE.md 内のコンパクション指示例 -->
When compacting, always preserve:
- The full list of modified files and their current state
- Active test commands and their most recent output
- Any PLAN.md contents
- The current branch name and open PR number
```

#### `@` インポート構文の活用パターン
```markdown
# CLAUDE.md

See @README.md for project overview and @package.json for available npm commands.

## Git Workflow
See @docs/git-instructions.md

## Personal Overrides
@~/.claude/my-project-instructions.md
```

インポート先ファイルは必要時だけ読み込まれるため、CLAUDE.md 本体を 200 行以内に保ちながら必要情報を参照できる。

#### CLAUDE.md 配置場所の全パターン
| 場所 | 用途 |
|------|------|
| `~/.claude/CLAUDE.md` | 全セッション共通のグローバル設定 |
| `./CLAUDE.md` | プロジェクト共有設定（git 管理） |
| `./CLAUDE.local.md` | 個人専用プロジェクト設定（gitignore 推奨） |
| 親ディレクトリ `../CLAUDE.md` | モノレポのルートポリシー |
| 子ディレクトリ `src/api/CLAUDE.md` | そのディレクトリのファイルを読むときに自動ロード |

**適用提案**:
- CLAUDE.md に `When compacting, always preserve: [修正ファイルリスト、テストコマンド、PR番号]` を追記し、長時間セッションのコンパクション後も重要情報が失われないようにする
- `@docs/architecture.md` のインポートを活用し、アーキテクチャ文書は CLAUDE.md 本体に書かずに参照するだけにする

### ワークフロー ― Stop フック検証ゲートとプロンプト設計

**発見内容**: 公式ドキュメントで検証ゲートとしての Stop フック活用法が体系化された。

#### 検証強度の 4 段階
| 段階 | 方法 | 適したケース |
|------|------|-------------|
| プロンプト内 | `run the tests after implementing` | 通常のタスク |
| `/goal` 条件 | evaluator サブエージェントが毎ターンチェック | 長時間自律タスク |
| Stop フックゲート | スクリプトが fail すると Stop をブロック | ゼロ例外が必要な品質ゲート |
| 検証サブエージェント | 別コンテキストで結果を反証しようとする | 高精度が必要な実装 |

#### プロンプト品質テンプレート（ビフォーアフター）
```
❌ "add tests for foo.py"
✅ "write a test for foo.py covering the case where the user is logged out. avoid mocks."

❌ "fix the login bug"
✅ "users report login fails after session timeout. check src/auth/ especially token refresh.
    write a failing test that reproduces the issue, then fix it."
```

**適用提案**:
- ビルド・リントを Stop フックゲートに追加し、Claude が「完了」と言ってもチェックが通らない限り終了できないようにする
- 大型機能では `/goal "全テストが passing かつ lint エラーゼロ"` を設定し自律完了条件を明示する

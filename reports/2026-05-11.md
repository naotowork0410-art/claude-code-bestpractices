# Claude Code ベスプラ調査レポート 2026-05-11

## 今週の新発見

### Routines ― スケジュール実行・イベントトリガー型タスク自動化

**発見内容**: 2026年4月14日に発表された **Routines** 機能（研究プレビュー）が、Claude Code の自動化能力を大幅に拡張した。Routines は「プロンプト + リポジトリ + コネクタ（GitHub・Linear・Slack等）」をひとまとめにした設定ユニットで、以下のトリガーで自動実行される:

- **スケジュール**: cronライクな定期実行（例: 毎朝9時にコードレビュー）
- **API呼び出し**: 外部システムからHTTPで起動
- **GitHubイベント**: PRオープン・新規Issue作成など

実行はAnthropicのクラウドインフラ上で行われ、**ローカルマシンの起動不要**。夜間バッチ（例: 深夜2時にLinearバックログのバグをトリアージ）なども可能。

**プラン別の1日あたり実行上限**:
| プラン | 上限 |
|--------|------|
| Pro | 5回/日 |
| Max | 15回/日 |
| Team / Enterprise | 25回/日 |

**典型的なユースケース**:
```
# 毎朝実行する自動コードレビューRoutine例
プロンプト: "前日の全PRをレビューし、セキュリティ問題・パフォーマンス懸念・
            テスト不足を検出してSlackにサマリーを投稿してください"
リポジトリ: github.com/myorg/myrepo
コネクタ: GitHub PR, Slack
スケジュール: 毎朝 09:00 JST
```

**適用提案**: デスクトップアプリの「Scheduled tasks」（または `/routines`）から設定する。まずは「週次の依存パッケージ監査」「PRがマージされたら変更サマリーをSlackに通知」など小さなRoutineから始める。CI/CDと組み合わせると GitHub Actions の代替として機能する。

### `/btw` コマンド ― コンテキストを汚さない側聞き

**発見内容**: v2.1.72（2026年3月10日）で追加された `/btw`（By The Way）コマンドが、コンテキスト効率を劇的に改善する実用的な手法として確立した。

**動作の特徴**:
- Claude が作業中でも**割り込まずに**質問できる（生成が終わるのを待たなくてよい）
- 回答は**ディスミス可能なオーバーレイ**で表示され、会話履歴に一切追加されない
- 現在のセッションコンテキスト（読んだファイル、実行したコマンド等）を**完全に参照できる**
- 親会話の**プロンプトキャッシュを再利用**するため、追加トークンコストは最小
- ツールアクセスなし（ファイル読み込み・コマンド実行は不可）

**サブエージェントとの使い分け**:
| 用途 | 手段 |
|------|------|
| 現在のセッション知識を問い合わせる（ツール不要） | `/btw` |
| 新しいファイル・情報を調査する（ツール必要） | `use a subagent to investigate...` |

**使用例**:
```
# Claudeがファイルを編集している最中に
/btw この関数の引数の型は何でしたっけ？

# 長いテスト実行中に
/btw テスト完了したらどのブランチにプッシュすればいい？
```

**適用提案**: `npm test` 実行中・大きなリファクタリング実行中など「待ち時間」に `/btw` で関連質問をする習慣をつける。従来は「Claudeが終わるのを待って→質問→コンテキストが膨らむ」だったフローが「並行して質問→コンテキスト節約」に変わる。

### セッションテレポーテーション & リモートコントロール

**発見内容**: Claude Code がクラウド↔ローカル↔モバイルをシームレスに行き来できる**セッション転送機能**が整備された。

#### `--remote` フラグ: CLIからクラウドセッション起動
```bash
# ローカルCLIからクラウドセッション（claude.ai/code）を起動
claude --remote "src/auth/login.ts の認証バグを修正して"
```
タスクはクラウドVMで実行され、ローカル作業を続けながらバックグラウンドで進む。

#### `--teleport` / `/teleport`: クラウド→ローカル転送
```bash
# インタラクティブにセッションを選択してローカルに転送
claude --teleport

# セッションIDを指定して直接再開
claude --teleport <session-id>
```
会話履歴・コンテキスト・作業ブランチがすべてローカルターミナルに引き継がれる。

#### `/remote-control`: ローカルセッションをモバイル/Webから操作
```bash
# インタラクティブセッション内で実行
/remote-control
```
または `/config` で「Enable Remote Control for all sessions」を有効化すると、スマートフォンのClaudeアプリやWebブラウザから実行中のローカルセッションを操作できる。

**適用提案**:
- 長時間タスク（大規模リファクタリング等）は `claude --remote` でクラウドに投げてPCをシャットダウン
- 外出先でスマートフォンから `/remote-control` でセッション状況確認・指示変更
- `/config` で Remote Control を常時有効化しておくと利便性が高い

### Claude Code on the Web ― クラウド実行の詳細と自動PR修正

**発見内容**: `claude.ai/code` でのクラウド実行が研究プレビュー（Pro・Max・Team・Enterprise対象）として本格稼働。**自動PR修正機能**が特に強力。

**主要機能**:

#### セッション継続性
- ブラウザを閉じてもセッションは**継続実行**
- iOSアプリからセッション状況をモニタリング可能
- `claude --teleport` でローカルに転送して引き続き作業

#### 自動PR修正（Auto-fix Pull Requests）
```
# claude.ai/code でPRをモニタリング設定すると:
1. CIチェック失敗 → 自動的に失敗を分析して修正コミットをプッシュ
2. レビューコメント → 自動的に対応する変更を加えてPRを更新
3. 全チェック通過 → 自動マージ（設定時）
```

#### セットアップスクリプト（環境構成）
クラウドVMに依存関係をインストールするスクリプトを `.claude/setup.sh` として定義できる:
```bash
# .claude/setup.sh
#!/bin/bash
npm install
pip install -r requirements.txt
cp .env.example .env
```

**ネットワークアクセスレベル**:
| レベル | 説明 |
|--------|------|
| Default | Anthropic管理の許可リストのみ |
| Extended | 追加ドメインを許可 |
| Open | 全インターネットアクセス |

**適用提案**: PRの `Auto-fix` 機能を有効化するだけで、CI失敗の手動対応が大幅に削減される。`claude.ai/code` でリポジトリを接続し、「Monitor this PR」をオンにする。長時間タスクは Web で起動してローカルは別作業に使う。

### デスクトップアプリ再設計 ― Cowork タブ・SSH・サイドチャット

**発見内容**: 2026年4月14日リリースのデスクトップアプリ（Mac/Windows）が3タブ構成に刷新された。

**3タブの役割分担**:
| タブ | 説明 |
|------|------|
| **Chat** | ファイルアクセスなしの一般会話（claude.ai相当） |
| **Cowork** | クラウドVMで動く自律エージェント（バックグラウンド実行） |
| **Code** | ローカルファイルへの直接アクセス付きインタラクティブコーディング |

**新機能ハイライト**:
- **SSH接続**: リモートサーバー・クラウドVM・devコンテナに接続。デスクトップが自動的にClaude Codeをリモートにインストール
- **PRモニタリング + 自動マージ**: CIチェック結果を監視し、通過後に自動マージ
- **サイドチャット**: メインセッションを妨げずに質問できる（CLIの `/btw` 相当）
- **アプリプレビュー**: devサーバーをデスクトップ内で起動し、Claudeが画面を見てUIをテスト・修正
- **スケジュールタスク**: Routinesと連携した定期実行
- **ドラッグ&ドロップレイアウト**: チャット・diff・ターミナル・ファイル・プレビューを自由配置

**適用提案**: **Cowork タブ**は「バックグラウンドで動かしっぱなしのエージェント」として最適。Codeタブで通常作業しながら、Coworkタブでドキュメント生成・テスト拡充・依存更新などを並行実行する。

### 公式ドキュメントの新しい実践パターン（2026年版）

**発見内容**: 公式ベストプラクティスドキュメントが2026年版に更新され、以下の具体的なパターンが新たに明記された。

#### `@` ファイル参照とデータパイプ
```bash
# CLIからファイル内容を直接パイプ
cat error.log | claude
git diff HEAD | claude -p "この差分のバグを特定して"

# プロンプト内でファイル参照
"@src/auth.ts を読んで認証フローを説明して"
```

#### CLAUDE.md の最小化原則（公式テスト基準）
公式ドキュメントが明記した「CLAUDE.md に書くかどうかの判断基準」:

> **「この行を削除したら Claude が間違えるか？」** → NOなら削除する

また、ルールの遵守率を上げるキーワード:
- `"IMPORTANT: ..."` 
- `"YOU MUST ..."`

**含める vs 除外する**（公式ガイドライン）:

| ✅ 含める | ❌ 除外する |
|-----------|------------|
| Claudeが推測できないBashコマンド | コードを読めばわかること |
| デフォルトと異なるコードスタイル | 言語の標準的な慣習 |
| テスト手順・優先テストランナー | 詳細なAPIドキュメント（リンクのみでよい） |
| ブランチ命名・PRルール | 頻繁に変わる情報 |
| 開発環境の注意点（必須環境変数等） | 「クリーンなコードを書け」のような自明な指示 |

#### 5つの公式アンチパターン（最新版）
1. **Kitchen sink セッション**: 無関係タスクをひとつのセッションで混在 → `/clear` で分離
2. **修正ループ**: 同じ問題を2回以上修正 → `/clear` して精確なプロンプトで再開
3. **肥大化 CLAUDE.md**: 長すぎてルールが無視される → 容赦なく削除、hookに変換
4. **Trust-then-verify ギャップ**: 検証なしに実装を信頼 → テスト・スクリプト必須
5. **無限探索**: スコープなしの「調査して」 → サブエージェントに委譲か範囲を限定

#### `/compact` ターゲット指定（新しい使い方）
```bash
# 特定の観点を保持しながらコンパクション
/compact Focus on the API changes

# 選択した地点から要約（/rewind と組み合わせ）
# Esc+Esc → チェックポイント選択 → "Summarize from here"
# → その地点以降だけを要約して以前のコンテキストは保持
```

**適用提案**:
- プロジェクトの CLAUDE.md を開き「削除したら Claude が間違えるか？」テストを実施してスリム化
- ルール遵守が悪い箇所には `IMPORTANT:` を頭に追加、または hook に変換
- 2回修正しても直らない場合は `/clear` ルールを習慣化
